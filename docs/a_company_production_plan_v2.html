✅ 確定済みの方針

🏢 サーバー: A社オンプレ 確定

A社の社内サーバー（Linuxサーバー）に Inquira をインストール。データは A社の建物内に保管。

  • OS: Ubuntu 22.04 LTS（推奨）または既存の Linux サーバー
  • スペック: 2GB メモリ / 4GB ディスク以上
  • 必須: Python 3.11+
  • 外部接続: Anthropic API への HTTPS 通信のみ

🔑 APIキー: 段階的移行方式 確定

運用安定までは本人キー、安定後に A社キーへ移行する 2 段構え。

フェーズキー請求方式期間目安
初期（運用立ち上げ）本人キー本人 → A社へ月額固定で請求1〜3ヶ月
安定後A社キー（A社のAnthropic契約）Anthropic → A社へ直接その後継続

切替時の作業（30分）:

  1. A社が Anthropic アカウントを作成 → API キー発行
  2. A社サーバーの .env の ANTHROPIC_API_KEY を A社キーに差し替え
  3. アプリ再起動 → 完了

🌐 ドメイン: そのまま inquira-ai.com 確定

既に取得済みの inquira-ai.com をマルチテナント運用で活用。A社専用の URL を払い出し:

  • A社専用 URL: https://a-company.inquira-ai.com（DNS 設定で追加）
  • A社オンプレでも HTTPS 化が必要 → A社の社内 DNS + 自己署名 SSL or Let's Encrypt（要相談）
  • 本格的なオンプレ運用なら、A社内 URL（例: http://faq.aaa-internal.local）も検討
💡 オンプレで完全閉域で運用する場合、inquira-ai.com は使用せず、社内DNSのホスト名を使用する選択もあり。A社情シスとキックオフMTGで決定。

🗂 ストレージパス: UIから設定可能 v0.8.0で実装済

A社情シスは .env を編集せずに、管理画面の「設定・出力」タブから FAQ 格納フォルダ・原本ファイル格納フォルダの保存先を変更できます。

  • 例: /opt/inquira/data/faq_master や /mnt/shared/inquira/raw など A社サーバーの任意のパスを指定可能
  • 書き込み権限を自動チェック
  • 親フォルダが無ければ自動作成
  • 設定は永続化（再起動後も維持）

検討2: データクレンジング方針 🔴 最優先

試験運用時に判明した課題:

  • messagesText_content.md（20万チャンク）が TF-IDF の精度を低下させた
  • 1,000件のチケットは全件取り込みではなく、パレート原則で上位 2〜3 割を選別
項目方針案
チャットダンプ取り込まない（隔離フォルダ）
チケット 1,000件Claude で自動分類 → 上位 200〜300 件を FAQ化
マニュアル類全て取り込む（重要度高）
更新頻度初期投入後、月1回の差分更新

検討3: 教育系マスキングプリセット適用の是非 🟡 中

選択肢効果推奨度
MASKING_INDUSTRY=general メール/電話/カード等の標準マスキングのみ。学校名は素通し。データの自然さが保たれる ★★★ 初期推奨
MASKING_INDUSTRY=education 上記＋ 学校名を全て [学校名] に置換。他校名は隠せるが、A社自校名も消える ★★（運用見て判断）
カスタムルール 「他校はマスク、A社自校は素通し」のカスタム実装（要追加開発 約2時間） ★（要望があれば）
⚠ 推奨: まず general で開始
A社の自校名（例: 東京○○中学校）も [学校名] に置換されてしまうと、検索精度が落ちる可能性大。最初は general で運用し、1〜2 週間データを見て判断するのが安全。
