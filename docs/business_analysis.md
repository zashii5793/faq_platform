# Inquira ビジネス用途分析

| 項目 | 内容 |
|---|---|
| 文書バージョン | 0.1 |
| 作成日 | 2026-04-26 |
| 目的 | 「社内問い合わせ非効率」を解決する汎用 B2B SaaS としての事業性評価 |

---

## 1. 結論（先に）

**強い事業機会あり。** ただし「LLM × RAG の社内 FAQ」は競合が増えつつあり、
**勝ち筋は "業界特化テンプレート + データ主権 + 既存ナレッジ活用の手軽さ"** の三点に絞ること。
タカヤ・教育系A社案件は **業界別プリセット第1号** として位置づけ、
横展開可能な"型"を作ることに集中する。

- 想定 ARR：3年目で **¥1.2〜2.4億**（10〜20社×¥10万/月）
- 損益分岐：5社で月次黒字化（開発/運用2名体制想定）
- 主リスク：大手SaaS（NotionAI, ChatGPT Enterprise, Glean）の汎用機能化

---

## 2. 解決する課題

### 2.1 どの企業にも普遍的に存在する症状

| 症状 | 典型的な現場 | 試算（従業員300名規模） |
|---|---|---|
| 同種反復質問 | 情シス、人事、総務、経理、製品サポート | 月500〜1,500件、対応工数 80〜250h |
| ナレッジ散在 | Slack、メール、Confluence、Drive、紙、個人PC | "探す時間"が1人あたり週2.5h |
| 新人教育コスト | 新卒・中途オンボーディング | 1名あたり初月50hを先輩が消費 |
| 担当者の属人化 | "あの人に聞かないと分からない" | 退職時のナレッジ流出リスク |

### 2.2 既存解決策と限界

| 解決策 | 限界 |
|---|---|
| FAQページ（手書き） | 更新されない／検索性が低い |
| 既存チャットボット（IBM, KARAKURI 等） | テンプレ運用で初期構築重い、対応FAQ数の上限 |
| Confluence/Notion検索 | キーワード一致のみ、自然言語Q&A不可 |
| ChatGPT個人利用 | 機密情報の社外送信リスク（Shadow AI問題） |
| ChatGPT Enterprise / NotionAI | 高額（¥3,000〜/人）、独自データ連携の自由度低 |

→ Inquira のポジション：**「既存ドキュメントを"そのまま"参照させたい中堅企業」**向けの軽量ソリューション。

## 3. 市場規模（TAM/SAM/SOM）

### TAM（日本国内 B2B 社内 FAQ／ナレッジマネジメント領域）
- 国内ナレッジマネジメント市場：**約400億円/年**（一般的な業界推計）
- うち AI/LLM 適用比率：今後3年で 20〜40% に拡大見込み
- TAM ≈ **80〜160億円/年**

### SAM（中堅企業 30〜500名規模、データ主権を重視するセグメント）
- 該当企業数：日本に約2.5万社（中小企業庁データ参考）
- 平均単価仮定：¥60万/年（¥5万/月）
- SAM ≈ **150億円/年**（仮：浸透率1%でも¥1.5億/年）

### SOM（3年以内に現実的に取れる範囲）
- 営業リーチ可能：100〜200社
- 成約率：5〜10%
- SOM ≈ **¥6,000万〜¥2.4億/年**（10〜20社×¥10万/月想定と整合）

## 5. 競合分析

| 競合 | 強み | 弱み（Inquira の機会） |
|---|---|---|
| **ChatGPT Enterprise** | ブランド・性能・統合力 | 高額 (¥6,000〜/人/月)、セットアップ重い、業界特化薄い |
| **NotionAI** | UI 統合、文書連携 | Notion 上のデータのみ、社内ファイルサーバ非対応 |
| **Glean** | 全社検索の強さ | エンタープライズ向け、価格・要員ハードル高い |
| **国内チャットボット (KARAKURI/sAI Chat)** | 国内サポート、業界経験 | テンプレ運用、自然言語Q&A弱、高額 |
| **OSS自前構築 (LangChain等)** | コスト最小 | 開発・保守工数大、セキュリティは自己責任 |

### Inquira の差別化（3点に集約）

1. **業界別プリセット**：マスキング辞書／用語集／プロンプトを業界ごとにテンプレ化
2. **データ主権**：全構成を自社／契約済みクラウドに置ける（ZDR/オンプレ対応）
3. **既存ドキュメント直接参照**：Notion/Drive/ファイルサーバを"そのまま"取り込める

## 6. 価格戦略

### プラン構成

| プラン | 月額 | 上限 | ターゲット |
|---|---|---|---|
| Free Trial | ¥0 | 14日・100文書 | 全顧客 |
| Standard | ¥30,000 | 1,000文書、SSO | 30〜100名規模 |
| **Enterprise** | **¥100,000〜** | 無制限・SLA・カスタム辞書 | **本命**（100〜500名） |
| Industry Pack | +¥30,000/月 | 業界プリセット込み | 教育・医療・金融 |
| On-Premise | 個別見積 | 自社ホスト+保守 | 100名以上、機密性重視 |

### 月100万 ARR 逆算
- パターンA：Enterprise 10社（¥10万 × 10）
- パターンB：Enterprise 7社 + Standard 5社 + Industry Pack 3件（¥70万 + ¥15万 + ¥9万 = 約¥94万）

→ パターンBの方が解約耐性高い（多角化）。

## 7. Go-to-Market 戦略

### Phase 1: 事例作り（〜6ヶ月）
- **タカヤ**：無料運用でユースケース蓄積。教育業界外の汎用ケースとして事例化
- **教育系A社様**：教育業界第1号事例。Industry Pack化のテンプレ作成
- 目標：3社の導入事例を web/note で公開

### Phase 2: 横展開（6〜18ヶ月）
- 業界カンファレンス／勉強会での発表
- パートナー（システム会社、IT商社）経由の販売チャネル開拓
- ターゲット：年商数十億規模の中堅企業の情シス部門
- 目標：月次5〜8件の商談、四半期で2〜3件成約

### Phase 3: スケール（18ヶ月〜）
- マルチテナント SaaS 化（ROADMAP Phase 3）
- セルフサーブ契約導線（クレジット決済→14日トライアル→自動課金）
- インサイドセールス1名追加
- 目標：年間10社以上の純増

## 8. リスクと対策

| リスク | 影響度 | 対策 |
|---|---|---|
| ChatGPT Enterprise/Glean が同等機能を低価格化 | 大 | 業界特化と国内ホスト主権で差別化、敢えて全業界は狙わない |
| LLM API の価格高騰／規約変更 | 中 | 複数プロバイダ抽象化（Anthropic + OpenAI + Bedrock）、ローカルLLM対応保険 |
| 顧客データ漏洩事故 | 大 | マスキング多層化、監査ログ、ZDR標準化、保険加入 |
| 単一顧客依存（タカヤや教育系A社様への過剰最適化） | 中 | 早期に第3・第4顧客を別業界で確保 |
| 初期1〜2年のキャッシュフロー | 中 | 開発を最小2名に絞る／タカヤを無料事例化で営業材料に |
| LLMハルシネーション事故 | 中 | 出典必須回答、未知質問は回答拒否、精度KPIで監視 |

## 12. 結論：このツールはビジネス用途として「やる価値がある」

- 課題の普遍性（どの会社にもある）と LLM 技術の追い風で **市場機会は明確**
- 競合は強いが、**業界特化＋データ主権**で中堅企業セグメントを取り切れる余地あり
- 月100万 ARR は2年で十分達成可能、5社黒字化ラインも現実的
- 既存案件（タカヤ・教育系A社様）が **そのまま事例化** できるのが最大の追い風

**注意点**：「汎用社内FAQ」だけだと差別化弱い。**最初の3案件で必ず1業界の"型"を作り切る**ことが事業化の生命線。
