# Inquira 試験導入マニュアル（1社 トライアル運用ガイド）

> 想定読者: ZAXEL 担当（zashii）と顧客側プロジェクト責任者・情シス
> 利用シーン: 1社目の試験導入（PoC〜本格運用判断まで）
> 期間: 4週間（標準）／状況により 6週間まで延長可
> このマニュアルは [setup_for_admin.md](./setup_for_admin.md)（運用リファレンス）と
> [customer_proposal.md](./customer_proposal.md)（提案資料）の **実行版** です

## 0. 試験導入のゴール

| 観点 | 達成条件 |
|---|---|
| 機能 | 既存マニュアル 10〜20本を取り込み、5名以上の社員が継続利用 |
| 品質 | 平均確信度 50% 以上、回答率 60% 以上 |

- [ ] Google Workspace を社員認証に使っている（プラン名: _____）
- [ ] サーバ／VM を1台用意できる（Mac mini / Linux VM / Windows いずれか）

### 2.2 ナレッジ準備チェックリスト

- [ ] 試験導入で取り込む文書を **10〜20本** 選定
  - 推奨：問い合わせが多いトピック上位（VPN/経費精算/勤怠/新人手続き 等）

- [ ] 機密情報（人事評価/給与/契約書）は **対象外** で合意
- [ ] 取り込み後の「正解」を 5〜10件の Q&A ペアで合意

### Week 1: セットアップ（情シス担当 4〜8 時間）

#### Day 1-2: 環境構築

```bash
# ① コード取得
git clone https://github.com/zashii5793/faq_platform.git
cd faq_platform

# ② Python 3.11+ で仮想環境
uv venv --python 3.11   # またはお手元のPython 3.11 で
source .venv/bin/activate
uv pip install -e ".[dev]"

# ③ テスト確認（依存正しさの確認）
pytest -q   # 120件PASSなら準備OK

# ④ .env 作成
cp .env.example .env
nano .env
# ANTHROPIC_API_KEY=sk-ant-api03-...
# CLAUDE_MODEL=claude-haiku-4-5-20251001
# ORG_NAME=○○株式会社
# ASSISTANT_ROLE=社内ヘルプデスク
# SESSION_SECRET=（openssl rand -hex 32 で生成）
```

#### Day 3: Google OAuth 設定

[google_oauth_setup.md](./google_oauth_setup.md) に従って設定（所要1時間）。
- [ ] OAuth 同意画面を「内部」で設定
- [ ] クライアント ID/Secret を `.env` に追加
- [ ] `ALLOWED_DOMAIN=顧客ドメイン.co.jp` を設定

#### Day 4: 起動・接続確認

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

- [ ] `http://127.0.0.1:8000/` でログイン画面表示
- [ ] Google 認証 → チャット画面表示
- [ ] 許可ドメイン外メールでのログインが拒否される（403）
- [ ] LAN 内別端末（iPhone 等）からもアクセスできる

#### Day 5: 文書取り込み（5〜10本目安）

[setup_for_admin.md §4](./setup_for_admin.md#4-文書を取り込む) に従って：
- [ ] `/admin/upload` から 5〜10本をドラッグ&ドロップ
- [ ] クレンジング結果で PII 検出されたファイルを個別判定
- [ ] 取り込み完了（「3. 取り込み済み文書」に表示確認）

**Week 1 終了時の Output:**
- [ ] サーバ起動済み
- [ ] OAuth 認証稼働

## 4. 本格導入判断の基準

### ✅ Go の基準（すべて満たす）

- 回答率 60% 以上
- 平均確信度 50% 以上
- 試用ユーザー満足度 平均 3.5/5 以上
- 月間 API コストが想定内
- 情シス担当が自走でマニュアル追加できる

### ⚠ 改善継続の基準（一部欠ける）

- 回答率 50〜60% → ナレッジ不足、文書追加で改善見込み
- 確信度が低い → チャンク分割の見直し、文書のQ&A形式化

### ❌ No-Go の基準（撤退判断）

- そもそも試用ユーザーが使わない → ユースケース不一致
- API コストが想定の3倍以上 → BYO への切替で再評価
- セキュリティ要件（ZDR必須等）を満たせない → On-Premise 個別見積

## 5. 契約締結後の本格展開（試験 → 本番への移行）

判断が **Go** の場合：

| 項目 | 対応 |
|---|---|
| 契約書類 | 利用規約・プラポリ同意 → Stripe Payment Link で決済 |
| デプロイ | 本番 HTTPS 環境への移設（試用環境を流用 or 新設） |
| 全社展開 | 全社員アカウント発行・利用説明会・ヘルプデスクから誘導 |
| 運用引継ぎ | [setup_for_admin.md](./setup_for_admin.md) を情シス担当に渡す |
| サポート | プラン別 SLA に従う（Enterprise なら 1営業日対応） |

---

## 6. リスクと対策（試験期間中）

| リスク | 対策 |
|---|---|
| 試用ユーザーが質問しない | 案内メール再送、人気質問サジェスト機能を案内 |
| 回答品質が低い | チャンク分割見直し、Embedding バックエンド切替（e5-small） |
| API コスト超過 | Anthropic Console で月次 spend limit を設定（後述） |
| サーバが落ちる | 再起動手順を情シスに事前共有、Inquira は単一プロセスで復旧速い |
| 個人情報漏洩 | PII 自動マスキング + 監査ログ + 取り込み時のクレンジング画面確認 |
| 試用ユーザーが本機能を社外で話す | 試用前に守秘扱い周知（口頭でOK） |
