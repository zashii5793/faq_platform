🎯 Part 1: 先に決めるべき 5つの意思決定

これらが決まらないと作業計画が確定できません。A社との合意形成を最優先で。

決定1: ホスティング先 🔴 最優先 DECISION

選択肢月額設定難易度向き不向き
A) A社オンプレ
（社内サーバー）		 サーバー代込み
（既存資産活用なら +0円）		 🔴 難（半日〜1日） データ主権重視・既存サーバーあり
B) VPS
（さくらVPS/ConoHa/Linode等）		 2,000〜5,000円 🟢 易（2時間） 低コスト・スモールスタート
C) クラウド
（AWS/GCP/Azure）		 10,000〜30,000円 🟡 中（半日） スケール要件・将来の拡張
D) Render等のPaaS 0〜3,000円（Free〜Standard） 🟢 易（30分） PoC継続・運用工数最小
A社の場合、教育機関なので「データを社内に置きたい」要望が強いはず。
第1候補: A社オンプレ（情シスにLinuxサーバーがあれば）
第2候補: VPS（さくらVPS東京リージョン）（オンプレ不可なら、データ国内・低コスト）

決定2: Anthropic APIキー所有者 🔴 最優先 DECISION

方式請求メリットデメリット
方式X: 本人キー パススルー 本人 → A社へ実費転送 変動リスクなし、A社決算楽 月額が読みにくい、税務処理が手間
方式Y: A社キー直接 A社 → Anthropic 直接 本人介在なし、透明性最大 A社が技術的設定対応、海外送金
方式Z: 本人キー + 月額固定 本人 → A社へ月額○円固定（API込み） A社予算立てやすい、本人にマークアップ余地 本人が変動リスク負担
方式Z（月額固定・API込み）がA社・本人双方にとって扱いやすい。
「想定 ○○問/月までは月額○○円、超過分のみ実費精算」のハイブリッド設計。
目安: 35名規模・月15,000〜25,000円のAPI実費 → 月額40,000円（API+保守込み）など。

決定3: 認証方式 🔴 最優先 DECISION

方式前提運用負荷
① 現状のGoogle OAuth（test users方式） 手動でテストユーザー追加・100名上限 🟢 低（試験運用と同じ）
② Google OAuth 本番公開 OAuth verification 申請（1〜2週）・ドメイン認証必要 🟡 中（初回のみ手間）
③ Google Workspace SSO + 許可ドメイン A社がGoogle Workspaceドメイン保有 🟢 低（ドメイン名のみ.envに）
④ SAML/OIDC SSO A社がIdP（Microsoft Entra/Okta等）保有・Phase 3実装必要 🔴 高（追加開発・3週間〜）
A社が Google Workspace を使っていれば ③（ALLOWED_DOMAINで全社員自動許可）が最楽。
使っていない場合は ②（OAuth verification申請）で本番公開。

決定4: ドメインとURL 🟠 高 DECISION

選択肢URL例備考
現状の inquira-ai.com 継続 faq.inquira-ai.com 本人保有ドメイン、追加コストなし
A社既存ドメインのサブドメイン faq.aaa-corp.co.jp A社の管理下、信頼感↑、A社DNS設定要
A社用に新規ドメイン取得 aaa-help.com 等 独自感、取得費用 約2,000円/年
A社既存ドメインのサブドメインがベスト。
・ユーザーが「うちの会社のサービス」と認識して安心
・ブラウザ警告（試験運用時の「確認されていません」）が出にくい

決定5: 契約形態と料金 🔴 最優先 DECISION

項目選択肢
契約期間月次自動更新 / 年次一括 / 3年契約
料金体系月額固定 / ユーザー数課金 / 質問数課金
初期費用あり（○○円） / なし（月額に内包）
SLA業務時間内対応 / 24h対応 / なし
サポートメールのみ / 電話あり / オンサイトあり
初回案: 初期構築費 50,000円 + 月額 40,000円（API・保守・サポート込み）
・契約期間: 月次自動更新（縛りなしで導入決断しやすく）
・SLA: 業務時間内（9:00-18:00）対応、月の稼働率99%目標
・サポート: メール + Slack（A社のSlackに招待してもらう）
