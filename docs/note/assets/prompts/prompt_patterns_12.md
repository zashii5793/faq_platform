# Claude Code プロンプトテンプレート 12 型

コピーして `<>` を埋めて使う。

---

## 型 1：エラー診断

```
（ターミナルの出力を一切加工せず貼り付ける）

上記のエラーが出ました。原因の候補を可能性の高い順に 3 つと、
それぞれの切り分け方法を教えてください。
```

**要点**: 要約しない。実行ディレクトリ・パス・バージョン・スタックトレースの深さが診断の決め手になる。

---

## 型 2：コピペで動くコマンド

```
<やりたいこと> の手順を教えてください。
そのままターミナルに貼り付けて動く形で書いてください。
ディレクトリ移動も含めてください。
Windows の場合は PowerShell / コマンドプロンプトのどちらかを明記してください。
```

**要点**: 既定では「説明」が返る。翻訳工数を発生させない。

---

## 型 3：配布資料の生成

```
<内容> を <読者: 例「顧客の IT 部門」> にそのまま渡せる HTML で作ってください。
- チェックボックス付き
- フェーズごとに色分け
- 各ステップの所要時間を明記
- font-family には IPA フォントを含める（PDF 化時の中文化防止）
```

**要点**: 自分用メモと顧客配布資料が同時に手に入る。最も過小評価されている型。

---

## 型 4：棚卸し

```
これまでのやり取り、git 履歴、CHANGELOG から、
現在の残タスクを優先度順に整理してください。
「終わったこと」「進行中」「未着手」に分けてください。
```

**要点**: 週 1 で実行する。1 人開発が止まる最大の原因（現在地の喪失）を防ぐ。

---

## 型 5：フェーズ分割

```
<機能> を実装したいです。
まず全体を 3〜5 フェーズに分割した計画だけを提示してください。
実装はまだしないでください。
私が承認したフェーズだけを、1 つずつ実装します。
```

**要点**: 速いから任せるのではなく、速いから細かく切る。5 ファイル同時変更は切り分け不能になる。

---

## 型 6：スクリーンショット

```
（画面をキャプチャして添付）
この画面で <やりたいこと> をするには、どこを操作すればいいですか。
```

**要点**: クラウドコンソール類の UI は文章で説明しきれず、頻繁に変わる。

---

## 型 7：コミット前チェック

```
今からコミットしようとしています。
git の差分と .gitignore を確認して、
push してはいけない情報が含まれていないか確認してください。
特に API キー、OAuth シークレット、内部 IP、個人名、顧客固有の値。
```

**要点**: チェックリストを人間の記憶に頼らない。

---

## 型 8：TDD

```
<機能> のテストを先に書いてください。
重要: 「今の実装が通るテスト」ではなく「仕様として正しいテスト」を書いてください。
落ちても構いません。落ちたテストを見てから実装方針を決めます。
```

**要点**: 「落ちてもいい」を明示しないと、現状追認のテストが生成され何も検出しない。

---

## 型 9：設計批判

```
この設計の欠点を 3 つ挙げてください。
特に以下の観点で:
- データ量が 10 倍になったときに壊れる箇所
- 運用開始後に変更しづらくなる箇所
- 私が見落としている前提
```

**要点**: 既定では同意的。明示的に批判を要求すると質が変わる。

---

## 型 10：記録からの資料生成

```
CHANGELOG.md と git log から、
<期間> の成果を <用途: 例「顧客への月次報告」> 用にまとめてください。
技術用語は読者に合わせて調整してください。
```

**要点**: 記録を書くコストが投資に変わる。

---

## 型 11：実測

```
<対象> の性能を実測するベンチマークスクリプトを書いてください。
- データ量を 100 / 500 / 1000 / 2500 / 5000 と変えて計測
- 平均と p95 を出す
- 改善前後で比較できる形式で結果を保存
結果は顧客説明に使うので、表形式でまとめてください。
```

**要点**: 「速いです」は提案で通用しない。「5,000 文書で 5ms」が通用する。測定依頼がそのまま営業資料になる。

---

## 型 12：公開資料

```
これは社外に公開する資料です。
以下を一切含めないでください:
- 個人名（役割名に置き換える）
- 顧客の実名・ドメイン・IP アドレス
- 内部のファイルパス、サーバー名
- 生成時点で古くなる可能性のある数値（出典と日付を明記する）
```

**要点**: AI は「この文章がどこまで公開されるか」を知らない。宣言は指示側の責任。

---

## 使い分けマトリクス

| 場面 | 使う型 |
|---|---|
| バグが出た | 型 1 → 型 5 |
| 新機能を作る | 型 8 → 型 9 → 型 5 |
| 顧客に資料を出す | 型 3 → 型 12 → 人間レビュー |
| 進捗が分からなくなった | 型 4 → 型 10 |
| 性能を主張したい | 型 11 |
| コミット前 | 型 7 |
