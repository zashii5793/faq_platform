## note への掲載手順

### 1. 有料エリアの境界 — **第 3 章「捨てた① データベース」の直後**

本文中の以下の行が境界。note の「ここから先は有料エリア」をこの位置に設定する。

```
<!-- ===== ここから有料エリア ===== -->
```

具体的には、**「❌ 捨てた② ベクトルデータベース」の見出しの直前**。

#### 無料で読める範囲（記事全体の約 15%）

| 章 | 内容 | 無料にする理由 |
|---|---|---|
| 0 | 何が手に入るか / **買うべきでない人** / 買うべき人 | ミスマッチ購入を防ぐ。高額商品では、期待外れの低評価を避けることが 1 件多く売るより価値が高い |
| 1 | 何を作ったのか + **実数値**（コード 6,814 行 / テスト 377 本 / 検索 5ms / API 2〜3 円） | 「本当に作って納品した人」だと証明する。ここが無いと read すらされない |
| 2 | **用語解説の全文**（RAG / チャンク / TF-IDF / BOM / xfail …） | 「この人は初心者にも分かるように書ける」と伝わる。単体で検索流入・SNS 拡散の受け皿にもなる |
| 3-1〜3-2 | 全体構成図・技術スタックと選定理由 | 中身の密度を先に見せる |
| 3-3 の「捨てた① データベース」 | **1 項目だけ完全公開** | ここが最重要 ↓ |

#### なぜ「捨てた①」を丸ごと見せてから切るのか

高額記事では、**「濃さの実物を 1 個見せてから切る」**のが最も転換率が高い。

「捨てた① データベース」は、採用理由・3 つの根拠・**トレードオフの正直な開示**まで含んだ
完結した 1 項目になっている。これを読み切った読者は「この密度が残り全部にある」と判断できる。

逆に第 1 章で切ると、読者が判断材料を持てないまま ¥24,800 の決済画面に来ることになり、
**内容は良いのに売れない**という形になりやすい。

#### 有料エリアの直前に置いてある「予告ブロック」

境界の直前に、この先に何があるかの箇条書き（引用ブロック）を入れてある。
note では課金判断がここで起きるため、**この 12 行が実質的な販売文**になる。
記事を改訂したら、この予告の内容も必ず合わせて更新すること。

#### 境界を変えたい場合

`<!-- ===== ここから有料エリア ===== -->` の行を動かすだけ。候補は 2 つ。

| 変更先 | 効果 |
|---|---|
| 第 2 章（用語解説）の直前まで戻す | 無料範囲が狭くなる。読者の判断材料が減り、転換率は下がりやすい |
| 第 4 章（こだわり）の直前まで進める | 「捨てた技術 4 つ」が全部無料になる。拡散力は上がるが、目玉のひとつを失う |

### 2. 記事の貼り付け — **Markdown をそのまま貼ってはいけない**

note のエディタはリッチテキストで、**Markdown 記法を解釈しない**。
テキストのまま貼ると `##` や `**` が文字として残り、レイアウトが崩れる。
さらに **note には表組みの機能自体が無い**ため、表は必ず壊れる。

#### ✅ 第 1 候補：docx 経由（最も確実）

**note は Word / Google ドキュメントからの貼り付けで書式を保持する。**
ブラウザからの HTML コピーは環境によってプレーンテキストに落ちることがあるため、
**docx 経由を第 1 候補にする**。

**Mac の場合**

1. `note_01_for_note_paste.docx` をダウンロード
2. **Pages で開く**（標準アプリ。Word でも可）
3. `Cmd + A` → `Cmd + C`
4. note の記事編集画面に `Cmd + V`

**Google ドキュメント経由（追加アプリ不要・最も安定）**

1. Google ドライブに `note_01_for_note_paste.docx` をアップロード
2. 右クリック →「アプリで開く」→「Google ドキュメント」
3. `Cmd + A` → `Cmd + C`
4. note に `Cmd + V`

> Google ドキュメントは note が最も素直に受け取る貼り付け元。
> 他でうまくいかない場合はこれを試す。

#### 第 2 候補：HTML 経由

1. `note_01_for_note_paste.html` を**ブラウザで開く**（ファイルをダブルクリック）
2. `Cmd + A`（Windows は `Ctrl + A`）で全選択 → `Cmd + C`
3. note の記事編集画面に `Cmd + V`

> Safari で書式が落ちる場合は **Chrome を試す**。ブラウザによってクリップボードに
> 載るデータ形式が変わるため、これだけで解決することがある。

#### どちらの経路でも保持されるもの

| 要素 | 貼り付け後の状態 |
|---|---|
| 見出し（`##` / `###`） | note の見出しスタイルとして反映される |
| 太字（`**x**`） | 太字として反映される。**`*` は残らない** |
| 箇条書き・番号付きリスト | リストとして反映される |
| 引用（`>`） | 引用ブロックとして反映される |
| コードブロック | 等幅の塊として貼られる（体裁が崩れたら「コード」スタイルを適用） |
| 表 | **箇条書きに変換済み**（`■ 見出し` + ぶら下げ項目） |

> 貼り付け直後に画像・区切り線の位置だけ確認すれば、ほぼ手直し不要。

#### 予備手段（テキスト版）

HTML の貼り付けがうまくいかない環境向けに `note_01_for_note_paste.md` も用意してある。
こちらは見出しが `【x】` / `◆ x`、表が `■` + `・` の箇条書きになったプレーンテキスト。
**`**` が残るため、貼付後に一括削除が必要**（エディタの置換 or `sed 's/\*\*//g'`）。

#### 原本を編集したときの再生成

```bash
SRC=docs/note/note_01_faq_tool_with_claude_code.md

# docx 版（第 1 候補）※ 初回のみ: cd docs/note/assets && npm install docx
python3 docs/note/assets/md_to_blocks.py "$SRC" /tmp/blocks.json
node docs/note/assets/to_note_docx.js /tmp/blocks.json docs/note/note_01_for_note_paste.docx

# HTML 版（第 2 候補）
python3 docs/note/assets/to_note_html.py "$SRC" docs/note/note_01_for_note_paste.html

# テキスト版（予備）
python3 docs/note/assets/to_note.py "$SRC" docs/note/note_01_for_note_paste.md
```

どちらのスクリプトも**コードブロックの中身は一切変更しない**
（付録の入れ子フェンス ` ```` ` の中の ` ``` ` も保持される）。

#### 表を「画像」で載せたい場合

比較表だけは画像のほうが読みやすいこともある。その場合は
`assets/skills/ja-pdf-export/SKILL.md` のフォント指定をそのまま使うこと
（指定しないと中国語書体で描画される）。ただし画像内の文字は検索もコピーもできないため、
**全部を画像にするのは避ける**。箇条書きを基本に、比較表だけ画像が現実的。

### 3. テンプレート（CLAUDE.md / Skill）の渡し方

**結論: A を主、B を「おまけ」で併記するのが最も確実。**

| 方式 | 購入者の受け取り方 | 手間 | 評価 |
|---|---|---|---|
| **A. 記事内に全文掲載**（実装済み） | コードブロックをコピー → 自分のエディタに貼って保存 | ゼロ | **主軸にする**。リンク切れが起きず、note 内で完結する |
| **B. Gist リンク** | 有料エリアのリンクを開き、コピー or Raw で保存 | 5 分 | **併記推奨**。「ファイルとして落とせる」体感価値が大きい |
| C. クラウドストレージ共有 | 共有リンクから ZIP をダウンロード | 5 分 | 可。ただしリンク管理が続く |
| D. private リポジトリ招待 | GitHub アカウントを送ってもらい招待 | 大 | 継続更新を売りにする場合のみ |

#### なぜ A が主軸なのか

note は**記事内にファイルを添付して配布する用途には向いていない**。
一方でコードブロックは**そのままコピーできる**ので、テンプレート配布と相性が良い。

そして購入者が実際にやる作業は「コピーして自分のプロジェクトに保存する」だけ。
**ファイルで渡さないと使えない、という性質のものではない**（テンプレートは全て単一のテキストファイル）。

記事側では **付録 G「テンプレートの設置方法」** で保存先を図示してある。

```
あなたのプロジェクト/
├── CLAUDE.md                 ← 付録 A（ルート直下に置くだけで有効）
└── .claude/skills/<名前>/SKILL.md   ← 付録 B
```

さらに「Claude Code 自身にファイルを作らせる」手順も付録 G に載せてあるので、
購入者がフォルダ作成に詰まることはない。

#### B（Gist）を併記する場合の手順

1. GitHub で **Secret Gist** を作成（URL を知っている人だけがアクセスできる。検索には出ない）
2. `CLAUDE.md` / 各 `SKILL.md` / チェックリストをファイルとして追加
3. Gist の URL を **有料エリア内**に記載する

> ⚠ Secret Gist は「URL を知れば誰でも見られる」。URL が転載されれば拡散する。
> 完全に防ぐ手段は無いため、**A を主軸にし、B はあくまで利便性のおまけ**と位置づけるのが安全。

#### 更新したときの扱い

テンプレートを改訂した場合、**記事本文（A）を書き換えれば購入者は最新版を読める**（note は購入後も本文更新が反映される）。
これも A を主軸にする理由のひとつ。記事末尾の「更新履歴」に改訂内容を追記しておくと親切。

## 価格設定についてのメモ

¥24,800 は、note の有料記事としては最上位帯（一般的な技術記事は ¥500〜¥3,000）。
この価格で成立させるには、**「記事」ではなく「テンプレート製品 + 導入知見」として売る**必要がある。
本記事はその前提で構成してある。

### 価格を支えている要素

| 要素 | 内容 |
|---|---|
| 再利用可能な資産 | テンプレート 9 点（CLAUDE.md / Skill 3 / プロンプト 12 型 / チェックリスト 3） |
| 検証可能な実数値 | コード 6,814 行・テスト 377 本・検索 5ms・API 1 質問 2〜3 円 |
| 設計判断の開示 | 「捨てた技術 4 つ」とその理由、ハルシネーション三重防御の実コード・しきい値・システムプロンプト全文 |
| 失敗の全件開示 | オンプレ導入の詰まり 13 件、アンチパターン 5 件、自分の技術的負債（main.py 4,471 行）も明記 |
| 再現手順 | 30 日スケジュール（日割り） |
| 対象読者の限定 | 「買うべきでない人」を先に明示 |

### 検討事項

- **販売初期は割引で実績を作る方法もある**
  （例: 先着 10 名 ¥9,800 →以降 ¥24,800。note は価格変更が可能）
- **記事②以降とのセット販売**（マガジン機能）で単価を正当化する構成も取れる
- 高額帯では「購入者限定の質問対応」を 1 回付けると、価格への納得感が大きく変わる
  （付ける場合は、対応範囲と期限を記事内に明記すること）
