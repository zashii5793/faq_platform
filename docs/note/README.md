## note への掲載手順

### 1. 有料エリアの境界

本文中の以下の行が、無料 / 有料の境界。

```
<!-- ===== ここから有料エリア ===== -->
```

- **この行より上**（第 0 章「何が手に入るか」〜 第 1 章「何を作ったのか」）を無料公開範囲にする
- 無料部分に「買うべきでない人」を明記してあるのは意図的。高額商品では、
  期待外れによる低評価を防ぐことが、追加の 1 件を売ることより価値が高い

### 2. 記事の貼り付け — **Markdown をそのまま貼ってはいけない**

note のエディタはリッチテキストで、**Markdown 記法を解釈しない**。
テキストのまま貼ると `##` や `**` が文字として残り、レイアウトが崩れる。
さらに **note には表組みの機能自体が無い**ため、表は必ず壊れる。

#### ✅ 正しい手順（HTML 経由）

**書式付きテキストとして貼れば、note は見出し・太字・リスト・引用を保持する。**
そのためブラウザを経由するのが最も崩れない。

1. `note_01_for_note_paste.html` を**ブラウザで開く**（ファイルをダブルクリック）
2. `Cmd + A`（Windows は `Ctrl + A`）で全選択
3. `Cmd + C` でコピー
4. note の記事編集画面に `Cmd + V` で貼り付け

これで以下が自動的に保持される。

| 要素 | 貼り付け後の状態 |
|---|---|
| 見出し（`##` / `###`） | note の見出しスタイルとして反映される |
| 太字（`**x**`） | 太字として反映される。**`*` は残らない** |
| 箇条書き・番号付きリスト | リストとして反映される |
| 引用（`>`） | 引用ブロックとして反映される |
| コードブロック | 等幅の塊として貼られる（体裁が崩れたら「コード」スタイルを適用） |
| 表 | **箇条書きに変換済み**（`■ 見出し` + ぶら下げ項目） |

> 貼り付け直後に画像・区切り線の位置だけ確認すれば、ほぼ手直し不要。

#### 予備手段（テキスト版）

HTML の貼り付けがうまくいかない環境向けに `note_01_for_note_paste.md` も用意してある。
こちらは見出しが `【x】` / `◆ x`、表が `■` + `・` の箇条書きになったプレーンテキスト。
**`**` が残るため、貼付後に一括削除が必要**（エディタの置換 or `sed 's/\*\*//g'`）。

#### 原本を編集したときの再生成

```bash
# HTML 版（推奨）
python3 docs/note/assets/to_note_html.py \
  docs/note/note_01_faq_tool_with_claude_code.md \
  docs/note/note_01_for_note_paste.html

# テキスト版（予備）
python3 docs/note/assets/to_note.py \
  docs/note/note_01_faq_tool_with_claude_code.md \
  docs/note/note_01_for_note_paste.md
```

どちらのスクリプトも**コードブロックの中身は一切変更しない**
（付録の入れ子フェンス ` ```` ` の中の ` ``` ` も保持される）。

#### 表を「画像」で載せたい場合

比較表だけは画像のほうが読みやすいこともある。その場合は
`assets/skills/ja-pdf-export/SKILL.md` のフォント指定をそのまま使うこと
（指定しないと中国語書体で描画される）。ただし画像内の文字は検索もコピーもできないため、
**全部を画像にするのは避ける**。箇条書きを基本に、比較表だけ画像が現実的。

### 3. テンプレート（CLAUDE.md / Skill）の渡し方

**結論: A を主、B を「おまけ」で併記するのが最も確実。**

| 方式 | 購入者の受け取り方 | 手間 | 評価 |
|---|---|---|---|
| **A. 記事内に全文掲載**（実装済み） | コードブロックをコピー → 自分のエディタに貼って保存 | ゼロ | **主軸にする**。リンク切れが起きず、note 内で完結する |
| **B. Gist リンク** | 有料エリアのリンクを開き、コピー or Raw で保存 | 5 分 | **併記推奨**。「ファイルとして落とせる」体感価値が大きい |
| C. クラウドストレージ共有 | 共有リンクから ZIP をダウンロード | 5 分 | 可。ただしリンク管理が続く |
| D. private リポジトリ招待 | GitHub アカウントを送ってもらい招待 | 大 | 継続更新を売りにする場合のみ |

#### なぜ A が主軸なのか

note は**記事内にファイルを添付して配布する用途には向いていない**。
一方でコードブロックは**そのままコピーできる**ので、テンプレート配布と相性が良い。

そして購入者が実際にやる作業は「コピーして自分のプロジェクトに保存する」だけ。
**ファイルで渡さないと使えない、という性質のものではない**（テンプレートは全て単一のテキストファイル）。

記事側では **付録 G「テンプレートの設置方法」** で保存先を図示してある。

```
あなたのプロジェクト/
├── CLAUDE.md                 ← 付録 A（ルート直下に置くだけで有効）
└── .claude/skills/<名前>/SKILL.md   ← 付録 B
```

さらに「Claude Code 自身にファイルを作らせる」手順も付録 G に載せてあるので、
購入者がフォルダ作成に詰まることはない。

#### B（Gist）を併記する場合の手順

1. GitHub で **Secret Gist** を作成（URL を知っている人だけがアクセスできる。検索には出ない）
2. `CLAUDE.md` / 各 `SKILL.md` / チェックリストをファイルとして追加
3. Gist の URL を **有料エリア内**に記載する

> ⚠ Secret Gist は「URL を知れば誰でも見られる」。URL が転載されれば拡散する。
> 完全に防ぐ手段は無いため、**A を主軸にし、B はあくまで利便性のおまけ**と位置づけるのが安全。

#### 更新したときの扱い

テンプレートを改訂した場合、**記事本文（A）を書き換えれば購入者は最新版を読める**（note は購入後も本文更新が反映される）。
これも A を主軸にする理由のひとつ。記事末尾の「更新履歴」に改訂内容を追記しておくと親切。

## 価格設定についてのメモ

¥24,800 は、note の有料記事としては最上位帯（一般的な技術記事は ¥500〜¥3,000）。
この価格で成立させるには、**「記事」ではなく「テンプレート製品 + 導入知見」として売る**必要がある。
本記事はその前提で構成してある。

### 価格を支えている要素

| 要素 | 内容 |
|---|---|
| 再利用可能な資産 | テンプレート 9 点（CLAUDE.md / Skill 3 / プロンプト 12 型 / チェックリスト 3） |
| 検証可能な実数値 | コード 6,814 行・テスト 377 本・検索 5ms・API 1 質問 2〜3 円 |
| 設計判断の開示 | 「捨てた技術 4 つ」とその理由、ハルシネーション三重防御の実コード・しきい値・システムプロンプト全文 |
| 失敗の全件開示 | オンプレ導入の詰まり 13 件、アンチパターン 5 件、自分の技術的負債（main.py 4,471 行）も明記 |
| 再現手順 | 30 日スケジュール（日割り） |
| 対象読者の限定 | 「買うべきでない人」を先に明示 |

### 検討事項

- **販売初期は割引で実績を作る方法もある**
  （例: 先着 10 名 ¥9,800 →以降 ¥24,800。note は価格変更が可能）
- **記事②以降とのセット販売**（マガジン機能）で単価を正当化する構成も取れる
- 高額帯では「購入者限定の質問対応」を 1 回付けると、価格への納得感が大きく変わる
  （付ける場合は、対応範囲と期限を記事内に明記すること）
