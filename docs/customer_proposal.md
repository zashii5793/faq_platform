## 2. Inquira が解決する仕組み

### 2.1 一行で言うと

> **「会社の中にある資料をすべて取り込んで、社員が自然言語で質問したら出典付きで答える AI 受付係」**

### 2.2 質問のフロー（裏側）

```
[社員] 「VPN繋がらない時どうしたら？」
   ↓ Web ブラウザ or iPhone Safari
[Inquira サーバ]
   ↓ 個人情報マスキング（メール・電話・マイナンバー等）
[検索エンジン]
   ↓ 関連文書 5件をピックアップ
[Claude AI]
   ↓ 文書内容のみを根拠に回答生成（推測禁止）
[社員] 「FortiClient を再起動 → ADパスワード確認 → 情シスに起票
        確信度 95% / 出典: VPN接続マニュアル.md」
```

### 2.3 「学習」ではなく「参照」する設計

よくある誤解：「AI に学習させる = 機密情報がモデルに残る」

**Inquira は学習させません。「参照」します。**

| | Fine-tuning（学習） | Inquira (RAG = 参照) |
|---|---|---|
| 文書の扱い | モデルに焼き込む | 質問のたびに関連箇所を抜き出して渡す |
| 機密保護 | モデルに混ざる | 御社サーバに残る・外部送信は最小限 |
| 更新 | 再学習が必要 | ファイル置くだけで即反映 |
| 出典 | 不明 | **必須・常に明示** |

> 御社の文書そのものは **絶対に外に出ません**。質問のたびに関連箇所だけ Anthropic API（学習に使われない契約）に送信されるだけです。

## 3. 製品仕様

### 3.1 対応データ形式

| 形式 | 取り込み方 |
|---|---|
| PDF | ページ単位でチャンク化、OCR は v2 で対応 |
| Excel (.xlsx) | シート × 行単位 |
| PowerPoint (.pptx) | スライド単位 + 発表者ノート |
| CSV | 行単位 |
| Markdown / テキスト | 段落・見出し境界で分割 |
| Google Drive | フォルダ単位同期（v2） |

### 3.2 セキュリティ機能

| 機能 | 内容 |
|---|---|
| **PII 自動検出** | メール・電話番号・マイナンバー・カード番号・IP・URL を検出 |
| **業界別マスキング** | 教育: 学校名 / 医療: 診療番号 / 金融: 口座番号 |
| **危険ファイル拒否** | マイナンバー含む CSV 等は取り込み自動拒否 |
| **チャンク単位除外** | 文書の一部だけ機密 → その部分だけ除外して残りを取り込み |
| **出典必須** | AI が「どこから持ってきたか」を必ず明示 |
| **ハルシネーション抑制** | 関連文書なし → AI を呼ばずに「該当情報なし」と返す |
| **監査ログ** | 全操作を JSONL 形式で記録（誰が・いつ・何を） |
| **Google SSO** | 社員 Workspace アカウントでのみログイン可 |

### 3.3 学習機能（RAG層）

「使うほど賢くなる」設計：
- 取り込み文書を増やす → カバー範囲が即時拡大
- 👍/👎 フィードバック → 検索ランキングが進化（最大 ±15% 倍率）
- 「該当情報なし」が頻発する質問 → 管理画面で「ナレッジ不足」として可視化

## 4. 検索精度

### 4.1 ベンチマーク結果（タカヤモーター 27 質問で測定）

| バックエンド | 関連質問の正解率 | ノイズ抑制 | 総合精度 |
|---|---|---|---|
| TF-IDF（軽量・デフォルト） | 71% | 100% | **74%** |
| **multilingual-e5-small** | 85〜88% (見込み) | 100% | **87% (見込み)** |
| **multilingual-e5-large** | 90〜95% (見込み) | 100% | **92% (見込み)** |

> 環境変数 1つ（`EMBEDDING_BACKEND=e5-small`）で切替可能。
> 第1号顧客では tfidf で開始 → 文書増加で e5 に切替が現実的。

### 4.2 「答えない」を正しく実装

普通の AI チャットボットの問題は **「知ったかぶり」**。
Inquira は文書内容に答えがなければ **明確に「該当情報なし」と返す**：

> 該当情報が見つかりませんでした。
> 取り込み済みドキュメントから関連内容を発見できませんでした。
> 別の表現で再度質問するか、社内ヘルプデスクに直接お問い合わせください。

これにより、**間違った回答で社員を混乱させる事故ゼロ**。

## 5. UI

### 5.1 PC ブラウザ（左サイドバー + チャット）

サイドバーに常時表示：
- 📊 **分析**: 今日の質問数・回答率・平均確信度・トップトピック
- 🕐 **問い合わせ履歴**: 直近8件、クリックで再質問
- 📚 **ナレッジ取り込み状況**: 文書数・チャンク数・カバー領域
- 💬 **フィードバック**: 👍/👎累計・改善要望リスト

### 5.2 モバイル（iPhone / Android）

整備工場・現場・外出先での使用想定：
- ハンバーガーメニュー (☰) でサイドバー出し入れ
- 縦長スマホでも見やすい1カラム表示
- iOS の自動ズーム防止対応

### 5.3 管理者向け（/admin/upload）

ドラッグ&ドロップで PDF・Excel 等を投入：
- ファイルごとのクレンジング結果カード
- 各チャンクの個別判定（OK / 要確認 / 危険）
- **チャンク単位で取り込み可否を選択可能**
- 一括操作: 全取り込み / 危険のみ除外 / 全スキップ

## 8. リスクと緩和策

| リスク | 対策 |
|---|---|
| AI が誤った回答をする | 出典必須＋確信度スコア＋ハルシネーション抑制で限りなく低減 |
| 機密データが外部送信される | PII 自動マスキング・商用 API（学習なし）・ZDR オプション |
| 社員が使わない | 質問サジェスト動的生成・モバイル対応・Slack 連携（v2） |
| 文書が増えて検索が遅くなる | Embedding+ベクトルキャッシュで対応・100ドキュメントまで <200ms |
| 退職者がアクセスし続ける | Workspace 側でアカウント停止 → 自動連動 |
