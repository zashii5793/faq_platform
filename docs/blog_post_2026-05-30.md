# 1人で1ヶ月、Claude Codeと作ったAI社内FAQ「Inquira」— 開発全記録と8つのつまずき、そして10のコツ

## はじめに

2026年4月、私は1つの仮説を検証するためにコードを書き始めました。

> **「中小企業にも、ChatGPTレベルの社内FAQを、データを外に出さずに導入できる時代が来た。なら、それを商品にできるはずだ」**

そして約1ヶ月後の今日（2026年5月30日）、自社開発の社内ヘルプデスクAI **Inquira** が、教育系のA社（仮称）への試験運用を開始できる状態まで到達しました。

公開URL: `https://faq.inquira-ai.com`

- v0.7.2（バージョン7回のメジャー更新）
- 293件のテスト（カバレッジ88%）
- 5,000チャンクの検索が5.2ms（p95: 5.4ms）
- スループット200 QPS
- 月額API実費の試算 15,000〜25,000円（35名規模）

これを **一人で**、**Claude Code を相棒に** 作りました。

この記事では、開発記録・つまずきポイント・Claude Code を使った開発で身についたコツを、できるだけ正直に共有します。同じようなプロダクト開発を考えている方、Claude Code を使い始めた方、AI開発の現場の手触りを知りたい方の参考になれば幸いです。

## なぜ作ったのか

きっかけは A社（教育系）からの相談でした。

> 「社内のヘルプデスクにDBチケットが1,000件溜まっているけど、毎日同じ質問がきて若手が消耗している。ChatGPTを使いたいけど社内データを送るのは怖い。何かいい方法はないか?」

このとき思ったのは、**「これ、A社だけの話じゃないな」** ということ。

- 中小企業の情シス部門 → 「パスワード忘れた」が毎日来る
- 学校事務 → 同じ書類の書き方を毎年新人に説明
- 製造業の現場 → ベテランの暗黙知が辞めると消える

**「同じ質問が繰り返される」「ナレッジが散在する」**は、業界横断的な課題でした。

そして、これを解決するために必要な技術ピースは、2026年時点で全部揃っていました:

| ピース | 何を解決するか |
|---|---|
| Anthropic Claude API（学習に使われない） | 「データ持ち出しが怖い」を解消 |
| ローカルホスティング（自社サーバ） | データ主権確保 |
| RAG（Retrieval-Augmented Generation） | 既存ドキュメントを根拠にAIが回答 |
| 多形式パーサ（PDF/Word/Excel/PPT/CSV/JSON） | 既存資料をそのまま活用 |
| Cloudflare Tunnel（無料） | 自宅PCでも安全に外部公開 |

これらを組み合わせれば、**月10万円 × 10社 = 月100万円**のマイクロSaaSが見える。1人で立ち上げて、A社で事例化して、横展開する。そういうプランを立てました。

## ぶつかった8つの壁

開発中、特に印象的だった「ハマり」を共有します。Claude Code に助けられたものもあれば、Claude Code でも解決に手間取ったものもあります。

### 1. はてなブログのエクスポートデータが「ノイズの塊」だった

ある日、テスト用に自分のブログ記事（9MB）を取り込んだら、回答品質がガクッと落ちました。

質問: 「矢部正秋の本の紹介をして」
回答: 「確信度0%」

でも、関連チャンクとして該当記事はちゃんと見つかっていたんです。

```
📄 zashii.hatenablog.com.export (1).md セクション 326
関連度 低 (0.06)
----- -------- AUTHOR: hideki5793 TITLE: よく読む本 ...
```

なぜ確信度0%なのか? チャンクの中身を見て愕然としました:

```html
<p class="p1"><span class="s1">だと思います。</span></p>
<p class="p2">&nbsp;</p>
<li><span class="hatena-asin-detail-label">発売日:</span>
```

**TF-IDF は単語の出現頻度で検索する** ので、HTMLタグ・メタデータ・スパムコメントだらけのテキストでは、本来の意味的キーワードがノイズに埋もれて関連度スコアが0.06に。

**学び**: AIの精度はモデルじゃなくて**入力データの質**に大きく左右される。「とにかく全部取り込めばいい」は罠。

**対策**:
1. クレンジングスクリプトでHTMLタグを除去（即効）
2. EmbeddingバックエンドをTF-IDFからe5-smallに切り替え（中長期）

### 2. A社の実データ200MB+取り込みでインデックスが壊れた

似た問題で、A社のチャットダンプ `messagesText_content.md`（チャンク数 約20万）を取り込んだら、検索精度が全体的に低下。

原因: **1ファイルだけでコーパス全体の語彙を埋め尽くしてTF-IDFのIDF値を希薄化**。本来該当するマニュアルPDFのチャンクが、量で負けて検索結果から落ちる。

**対策**: 検索精度に悪影響を及ぼすファイルを `data/_quarantine/` に隔離する運用ルールに変更。

### 3. Embeddingキャッシュ再構築に「30分〜2時間」

20万チャンクで埋め込み計算する初回コストは仕方ない。問題は **1ファイル追加するたびに全件再計算** していたこと。

```
1ファイル追加: 30分〜2h ← これは耐えられない
```

これを Claude Code と一緒にリファクタ:

- 旧: 全コーパスをハッシュしてキャッシュ
- 新: `(chunk_id, text_hash)` 単位でキャッシュ

結果:

```
初回: 30分〜2h (変わらず)
1ファイル追加: 数秒  ← !!!
1ファイル更新: 数秒
1ファイル削除: 即時
```

「定期更新が前提の運用」が現実的になりました。

### 4. Apple Silicon に Intel バイナリを入れていた問題

今週、Cloudflare Tunnel をインストールしようとして、

```bash
$ cloudflared --version
Illegal instruction: 4
```

「Illegal instruction」= CPU命令セットが合っていない、というエラー。

原因: 私のMacは Apple Silicon (arm64) なのに、Intel用Homebrew (`/usr/local/`) が入っていて、cloudflared も Intel バイナリだった。

```bash
$ uname -m
arm64
$ which brew
/usr/local/bin/brew  ← これは Intel 用
```

**対策**: Apple Silicon 用バイナリを公式から直接DL → `/usr/local/bin/` に配置。

```bash
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-darwin-arm64.tgz -o /tmp/cloudflared.tgz
cd /tmp && tar -xzf cloudflared.tgz
sudo mv cloudflared /usr/local/bin/cloudflared
```

これで動きました。**M1以降のMacユーザーは要注意ポイント**です。

### 5. Pythonバージョン違いで起動失敗

`./scripts/serve.sh` を実行したら:

```
❌ Python 3.9 は古すぎます。3.11+ が必要です
```

Macに標準で入っているPythonは古い。

**対策**: `PYTHON=python3.11 ./scripts/serve.sh` のようにバージョンを明示。スクリプトを `PYTHON` 環境変数で切替可能に設計しておいたのが効きました。

### 6. main ブランチに README しか無い問題

A社向け試験運用の準備中、Macで:

```bash
$ git clone https://github.com/zashii5793/faq_platform.git
$ cd faq_platform
$ ls -la
total 8
-rw-r--r--   1 zashii  staff  14  README.md
```

「**えっ、コードは!?**」

GitHub上の `main` ブランチには初期コミットしか入っていなくて、実装は全部 `claude/add-roadmap-docs-RmQNp` ブランチに居た、というオチ。

**対策**: `git checkout claude/add-roadmap-docs-RmQNp` で切り替え。

**教訓**: Claude Code で生成したブランチをそのまま使い続けるのは便利だけど、定期的にmainへマージしないと、こういう「本体がどこか分からない」状態になります。

### 7. PDFが中華フォントで生成された

今週の週次レポートをPDF化したら、漢字が**中国語フォント**で表示されました。

```python
from weasyprint import HTML
HTML(filename='report.html').write_pdf('report.pdf')
```

→ デフォルトフォントがCJK共通フォント（中国語優先）になっていた。

**対策**:

```python
from weasyprint import HTML, CSS
HTML(filename='report.html').write_pdf(
    'report.pdf',
    stylesheets=[CSS(string='body { font-family: IPAGothic, sans-serif; }')]
)
```

これで日本語フォントに固定。**WeasyPrint で日本語PDFを作る人は要注意**。

### 8. Claude Codeに名前を覚えられていた

これは笑い話的なものですが、ある時 Claude Code が生成した週次レポートに、

> 「担当: 石澤さん」

と書いてあって、「いや、これは公開資料だから本名NGよ」となりました。

**対策**: 「本人」に置換するよう Claude Code に依頼。

**教訓**: AI は会話のコンテキストから親しみのある呼称を使いがち。公開資料は最後に人間がレビューする工程が必須。

## Claude Codeで開発する10のコツ

1ヶ月使ってみて、効果的だった使い方をまとめます。

### コツ1: エラーログは「そのまま」貼る

整形・要約しない。ターミナルの出力をそのまま貼ると、Claude Codeは:

- どのコマンドを実行したか
- どのファイルパスでエラーが出たか
- どのバージョンを使っているか

を一発で読み取れます。「省略しよう」と思った情報が、診断の決め手だったりします。

### コツ2: 「視覚的なドキュメントを作って」と頼む

私は何度も「HTMLで分かりやすく」「PDFで」「視覚的に」と依頼しました。Claude Code は、

- 色分けされたチェックリスト
- フェーズマップ
- 統計の大きな数字表示
- タイムライン

など、テキストだけでは伝わらない情報を構造化してくれます。**自分用メモにも、社外配布資料にも、両方使える**のが最大のメリット。

### コツ3: 「いまどこまでやったか」を聞く

セッションが長くなると、自分でも何をどこまでやったか分からなくなります。

> 「これまでのやり取りから、私の残タスクを整理して」

と聞くと、リポジトリの状態・git履歴・会話履歴を全部見て、棚卸ししてくれます。**人間より整理が上手いです**。

### コツ4: 「コマンドはコピペで動く形で」と依頼する

```bash
cd ~/faq_platform && PYTHON=python3.11 ./scripts/serve.sh
```

のように **そのまま貼り付けて動くコマンド** を要求する。「○○のディレクトリで」のような自然言語指示だと、自分で考える手間が発生します。

### コツ5: 「ステップを分けて」と頼む

長い手順は1メッセージで全部出してもらうより、

> 「フェーズ1完了したら教えて。フェーズ2に進む」

のように段階的に進めた方が、エラーの切り分けがやりやすいです。

### コツ6: スクリーンショットを送る

「画面が違う」「メニュー名が違う」と感じたら、スクリーンショットを送るのが最短ルート。
特にGoogle Cloud Console や Cloudflare のダッシュボードはUI変更が頻繁で、文章で説明しきれないことが多いです。

### コツ7: 「これGitアップして大丈夫?」を必ず聞く

`.env` や秘密鍵を含むファイルを編集したら、コミット前に

> 「これGit に push しても大丈夫?」

と一言確認する。Claude Code は `.gitignore` の中身も含めて判断してくれます。

### コツ8: 「過去の作業ログから抜粋して」と頼む

`CHANGELOG.md`・git log・日報ファイルなど、プロジェクトに残された記録から、Claude Code が自動でサマリーを作ってくれます。**自分で書くより速く、漏れも少ない**。

### コツ9: 公開資料は最後に人間レビュー

これは絶対。AI が生成した資料には:

- 個人名がそのまま入っている
- 会社の正式名称が違う
- 数字が古い（生成時点の情報）

などのケースがあります。**公開前に「リネームミスや事実関係に間違いないか」だけは人間が確認**する。

### コツ10: 「機能完成」と「実運用準備」を分けて考える

Claude Code はコードを書くのが速い。なので「機能としては作れた」状態にすぐ到達します。

でも、**実運用に投入するには別の作業が必要**:

- ドメイン取得・DNS設定
- HTTPS化（証明書管理）
- 認証プロバイダ連携（OAuth）
- ファイアウォール・アクセス制御
- バックアップ運用
- ユーザ案内資料の整備

これらは「コード」じゃないので、AIに丸投げできず、自分で進める必要がある。**Claude Code はコード以外の作業もガイドしてくれるけど、判断は人間**です。

## マーケティングとしての気づき

これは技術以外の学びです。

### 1. 「データを学習に使われない」が刺さる

A社との会話で一番反応が良かったのは、**「Claudeは入力データを学習に使いません。Anthropicが商用契約として明示しています」** という事実。

ChatGPT を社内利用したい大企業の **9割が止まっている理由がこれ**。LLM自体は欲しいが、「うちのデータが他社のAIに学習されるのは絶対無理」という壁。

商用APIを使うだけで、この壁は越えられる。

### 2. 「自宅Macで運用」は意外と通る

A社への提案で「最初の試験運用は私のMacで動かします」と伝えると、最初は「えっ?」という反応。でも、

- データはあなたのオフィスから出ません（Cloudflare Tunnel経由でMacにアクセス）
- 試験運用なので **コストゼロで始められます**
- 本契約時にはVPSへ移行します

と説明すると、納得を超えて「**ハードルが下がった**」と感謝されました。
**初期コストゼロでPoCできる** のは、中小企業向けには大きい武器。

### 3. 「動くデモ」は資料100枚に勝る

A社に提案する時、PowerPoint のスライドより **実際にURLを開いて触ってもらう** 方が圧倒的に速い。

「これ、御社のマニュアルを取り込めば、5分で動きます」と言って、その場で取り込んで質問すると、表情が変わります。

### 4. 「事例化」を最初から設計する

A社の試験運用が成功したら、次は事例化コンテンツを作る予定です。

- 導入前後の Before/After
- API実費の実数値
- 質問削減率
- 利用者の声

これを **2社目以降の営業資料** にすることで、ゼロからの提案が「実績あります」に変わります。

- **CHANGELOG を律儀に更新してくれる**（一人開発でつい疎かになるところ）
- **エラーログから根本原因を推定するのが上手い**

## まとめ

1ヶ月の開発で得た最大の学びは:

> **「AI開発は、技術より運用設計と顧客対話の方が難しい」**

技術的なピースは全部揃っている時代になりました。LLM、Embedding、RAG、認証、HTTPS化、これら全部に成熟したツールがあります。

難しいのは:
- **どんな運用フローにすればA社が安心して使えるか**
- **どんな価格モデルが説明しやすく公平か**
- **データクレンジングの質をどう保つか**
- **試験運用から本番契約に持っていく営業設計**

これらは Claude Code でも完全に代替できなくて、**自分の経験・判断・対人スキル** が物を言います。

逆に言えば、**コードを書くだけの仕事はAIに完全代替されつつあるけど、ビジネスを作る人間の価値は逆に上がっている**、というのが私の実感です。
