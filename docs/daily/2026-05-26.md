## 1. テスト・診断で判明したこと

### 1-1. 確信度0%・「undefined」表示の根本原因
A社データで質問してもほぼ全て「確信度0%・undefined」になる事象を調査:

| 原因レイヤー | 内容 |
|---|---|
| **直接原因** | Anthropic API キーが無効 → サーバーが 502 を返却 |
| **誤表示の元** | JS が `r.ok` をチェックせず `data.answer` を読み、`undefined` を画面表示するバグ |
| **設定面の誤解** | 「DEMO_MODE を外してください」のバナーは認証スキップフラグの注意書きであり LLM とは無関係（同フラグは `scripts/demo.sh` が常時 ON にする仕様） |
| **キーが効かなかった真因** | Anthropic のクレジットは API キー単位ではなく **Workspace単位**。新規キーが旧キーと同 Workspace に居ない or Spend Limit が `$0` だった可能性 |

→ APIキー再発行＋設定見直しで解消。監査ログでも `AuthenticationError` が消えたことを確認。

### 1-2. 検索精度の低下原因を特定（最重要）
監査ログ10件を分析した結果、**`messagesText_content.md`（チャンク数約20万）が原因**と判明:

- このファイル1つで全コーパスの語彙を埋め尽くし、TF-IDF のIDF値を希薄化
- 真に該当するマニュアルPDFのチャンク（数〜数十件）がスコアで負けて 0% 扱いになる
- 失敗5件中3件は、本来該当するPDFが既に取り込まれていたが拾えていない
  - 例: 「媒体インポートについて手順を教えて」→ `01_募集_媒体インポート操作手順書.pdf` 取込済みだが上位5件は全て messagesText_content.md

**推奨対処**: messagesText_content.md を `data/_quarantine/` に退避し、サーバー再起動するだけで体感が一変するはず。

## 5. 知見・気づき

- **大規模データ取り込み運用では、ベクトル化の差分更新が必須**。今日の改修で実用レベルに。
- **TF-IDF は 100MB 超のコーパスで精度が劇的に落ちる**。Embedding 切替の閾値判断材料として有用な実例。
- **原本ファイルへの動線**は、OCR で頑張るより「人が見て確認」する設計のほうが速くて確実、という設計判断が現場の声と一致した。
