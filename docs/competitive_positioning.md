# Inquira 競合ポジショニング — Gemini × NotebookLM 連携を踏まえて

> **想定読者**: 営業・経営・プロダクト
> **目的**: 2026 年 6 月の Google「Gemini × NotebookLM 連携（Notebooks 機能）」リリースを受けて、Inquira がどう競合し、どこで勝ち、どこで負けるかを整理する。商談時のポジショニング、提案資料の差分強化、ターゲット顧客の絞り込みに使う。
> **対象アップデート**: Gemini アプリ内で NotebookLM のノートブックを「ソース」として指定可能になり、Drive 連携・チャット履歴の共有コンテキスト化・Gems（事前設定）への組み込みが可能になった機能。Workspace 商用版では入力データの学習利用は無し。
> **改訂履歴**: 2026-06-05 初版

---

## 1. 一行結論

> **Gemini × NotebookLM は「個人〜小チームの第二の脳」、Inquira は「全社ヘルプデスク基盤」。**
> 同じ "AI が社内資料に答える" カテゴリだが、想定ユーザーと運用責任の所在が違うため、**競合は限定的**。むしろ NotebookLM の普及はカテゴリ自体の啓蒙となり、Inquira にとっては市場拡大の追い風。

```
                  ┌───────────────────────────────────────────────┐

                  └───────────────────────────────────────────────┘
                              │                  │
            ┌─────────────────┘                  └─────────────────┐
            ▼                                                      ▼

                          中堅企業の総務/人事
  [Gemini × NotebookLM]                            [Inquira]
  Google エコシステム前提                           インフラ独立・自社サーバー
  Drive 整理力に依存                                情シスが集中管理
```

競合のスイートスポット: **Google Workspace を全社導入していて、情シスがそこそこ強く、かつ規制業界ではない 50〜300 名規模**。それ以外はどちらかが明確に向きません。

## 3. 機能比較

| 観点 | Gemini × NotebookLM | Inquira | 評価 |
|---|---|---|---|
| **データ保管場所** | Google Cloud（米国 or 選択リージョン） | 顧客サーバー内（オンプレ/VPS） | **Inquira 優位**（規制業界） |
| **提供者の物理アクセス** | Google が運営（運営は物理的に到達可能） | 弊社は SSH 権限なし（物理的に不可） | **Inquira 優位** |
| **学習への利用** | Workspace 商用版は No | API 経由・Anthropic も No | 同等 |
| **資料の自動更新** | Drive 連携で自動 | 管理画面からアップロード（手動 or API） | **Gemini 優位** |
| **全社ナレッジの一元化** | ノートブックは作成者単位で分散 | 一つのプラットフォームに集約 | **Inquira 優位** |
| **Web 検索 / Canvas / Deep Research 連携** | あり（Gemini エコシステム） | なし | **Gemini 優位** |
| **業界別マスキング** | なし（一律 Google ポリシー） | 一般/教育/医療/金融 別 | **Inquira 優位** |
| **監査ログ** | Workspace audit log | Inquira 側で全 JSONL 保存 | 同等〜Inquira |
| **ライセンスコスト** | Workspace + Gemini Business/Enterprise 全員分 | Inquira 月額 + API 実費 | 規模次第 |
| **依存先** | Google 1 社にロックイン | Anthropic API のみ（差し替え可能） | **Inquira 優位** |
| **オフライン/閉域網運用** | 不可 | 可（Anthropic API 経路だけ開ければよい） | **Inquira 優位** |
| **OS / クラウド要件** | Workspace 必須 | Linux サーバーがあれば何でも | **Inquira 優位** |

## 4. Inquira の決定的な優位性（3つ）

### ① データ主権 — 「物理的に Google も弊社も触れない」

NotebookLM のデータは Google Cloud 上に存在し、Google の従業員は理屈の上では到達可能（実際には厳格なアクセス制御がある）。一方 Inquira は **顧客サーバー内のディスクにしか存在せず、弊社は SSH 鍵を持たない**。

- 金融庁の FISC 基準、医療の HIPAA、教育の学籍データ、防衛・公的機関など、**「データを国内・社内に閉じる」が契約条件になる業界** では Gemini 系は最初の選定段階で外れる。Inquira はここで土俵に上がれる。
- 監査時に「データはどこにありますか？」と聞かれて **「貴社サーバーの /srv/inquira/data です」と一意に答えられる** のは Inquira の独占的価値。

### ② 全社ヘルプデスクという業務形態への最適化

NotebookLM は **「個人が自分の調査用にノートブックを作る」** ツールとして設計されている。組織で使うには次の課題が出る：

- **属人化**: 誰がどのノートブックを持っているか分散する
- **回答の不一致**: 同じ質問でも参照するノートブック次第で違う答えが返る
- **公式回答の欠如**: 「会社の公式回答」として運用するには別の統制レイヤーが必要
- **Drive 整理力に依存**: 元データの Drive が散らかっていると役に立たない

Inquira は最初から **「全社員が同じ FAQ に質問し、情シスが一元管理する」** モデル。フィードバック学習も組織単位で蓄積される。

### ③ ベンダーロックインからの自由

- NotebookLM を使うには Workspace を契約し続ける必要がある。Workspace から離脱したらノートブックも消える。
- Inquira は OSS ベース・Docker 配布で、API 提供元（Anthropic）も将来差し替え可能。**顧客の選択肢を残せる** こと自体が中長期の優位性になる。
- Microsoft 365 中心の企業、独自 SSO を使う企業、特殊な業務システムと統合したい企業など、Workspace 前提では届かない層にリーチできる。

## 5. Gemini × NotebookLM の優位性（正直に）

Inquira が負けるポイントも明確にしておく：

- **Google エコシステムとの一体化**: Drive・Docs・Gmail・カレンダーから自動でソースが更新される。Inquira は手動アップロード or API 連携が必要。
- **Web 検索 / Canvas / Deep Research との掛け合わせ**: Gemini 側の高機能をそのまま使える。Inquira は単機能（社内 FAQ）。
- **個人の生産性ツールとしての即時性**: 今日設定して今日使える。Inquira は 30 分のデプロイが必要。
- **Workspace ライセンスへの付帯感**: 既に Workspace を契約している企業なら追加コストが見えにくい。
- **チャット履歴の共有コンテキスト化**: Gemini との会話自体がノートブック側に蓄積されて知識ベースが「育つ」。Inquira は質問→回答→ナレッジ化が手動 (👍/👎 とフィードバック反映)。

> **Inquira の機能ロードマップへの示唆**:
> NotebookLM の「会話履歴を共有コンテキスト化」は強力なアイデア。
> Inquira でも将来的に「解決した会話を自動で FAQ 候補に昇格させる」フローを実装する余地あり。

## 6. ターゲット顧客の使い分け

| 顧客像 | 推奨 |
|---|---|
| 金融・医療・教育・公的機関・防衛など規制業界 | **Inquira 一択**。データの物理所在が契約条件 |
| 全社員 300 名以上・情シスが強い・ヘルプデスク削減が目的 | **Inquira 優位**。NotebookLM は属人化する |
| Google Workspace を全社採用していて、20〜50 名の機動的なチーム | NotebookLM の方がフィット。Inquira は売り込まない |
| 個人事業主・小規模スタートアップ | NotebookLM の方が安い・速い。Inquira は売り込まない |
| Workspace 未導入 / Microsoft 365 中心 | **Inquira 優位**。NotebookLM の前提が崩れる |
| 国内オンプレ要件 / クラウド禁止 | **Inquira 一択** |
| 既に NotebookLM を試しているが「全社展開で詰まっている」企業 | **Inquira の出番**。「個人ツールから組織基盤へ」のリプレースを提案 |
| 海外子会社を含む多国籍企業 | リージョン要件次第。データ主権要件あれば Inquira、Google で揃えたいなら NotebookLM |

## 7. 商談での想定 Q&A

| 質問 | 切り返し |
|---|---|
| 「NotebookLM で十分じゃない？」 | 「個人で使うなら最高です。ただ全社員 100 名が同じ質問をしたとき、誰のノートブックを参照しますか？ Inquira は最初から組織用に設計されています」 |
| 「Google が持つ方が安全では？」 | 「Google が信頼できないという話ではなく、"絶対に外に出せない契約の機密" を扱う場面の話です。Inquira は弊社ですらアクセスできない構成なので、誰を信じる/信じない の議論が発生しません」 |
| 「Drive 連携で勝手に更新されるのは便利」 | 「同じ仕組みは Inquira でも構築できます (API 連携)。ただし、間違った文書が自動で混入するリスクもあるため、情シスがレビューしてから取り込む運用にしている企業も多いです」 |
| 「Workspace 払ってるから追加投資したくない」 | 「Workspace の Gemini 機能は使い続けながら、ヘルプデスク用途だけ Inquira に切り出すことも可能です。共存できる前提です」 |
| 「NotebookLM もデータ学習しないと言ってる」 | 「学習しないのは同じです。違いは『保管場所』と『運営者の物理アクセス権』です。Inquira の場合、弊社は SSH 鍵すら持たないので、技術的に到達不可能です」 |
| 「Gems で同じことできるのでは？」 | 「Gems は事前プロンプトの仕組みであり、データの保管場所は Google のままです。物理層・契約層の安心は別の話になります」 |

## 8. ポジショニング・ステートメント

商談初期に出すならこの一文：

> **「NotebookLM は個人の第二の脳。Inquira は会社の共有頭脳。」**
> **「Google が信頼できないという話ではなく、Google にも弊社にも預けられない情報のための場所を作る、というのが Inquira の存在理由です。」**

提案書に1行加えるならこの一文：

> 既存の SaaS 型 AI ナレッジツール（NotebookLM 等）が「組織展開で詰まる」典型課題に対し、Inquira は最初から **データ主権 × 全社ヘルプデスク基盤** として設計されています。
