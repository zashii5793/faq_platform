## 0. 設計原則

1. **左サイドバーで利用状況・ナレッジ状態を常時可視化** — 「どの程度学習が進んでいるか」「過去にどんな質問が来たか」を一目で把握できる
2. **サジェスト・分析は取り込みデータ駆動** — 文書を追加すると自動でサジェストとカバレッジが更新される（ハードコード禁止）
3. **業界プリセットなどの開発者設定は隠す** — エンドユーザー画面には出さず、歯車アイコンの開発者ツールに格納
4. **回答には必ず出典を付ける** — ハルシネーション防止のための強い設計制約

## 2. サイドバー仕様（左 280px 固定）

### 2.1 ヘッダー部
| 要素 | 内容 |
|---|---|
| プロダクト名 | `Inquira`（青字、大） |
| 組織名 | `[組織名]株式会社`（グレー、小） |

### 2.2 📊 分析セクション
**目的**：管理者・利用者が「ツールがどれだけ使われ／どれだけ役立っているか」を即座に把握。

| 項目 | データソース | 例 |
|---|---|---|
| 今日の質問数 | 監査ログから当日件数を集計 | `12件` |
| 平均関連度スコア | 各回答の上位ヒットスコアの平均 | `0.34` |
| トップトピック | top1ヒット文書の出現頻度 | `経費精算 (5)、VPN (3)` |

### 2.3 🕐 問い合わせ履歴セクション
**目的**：過去質問の即時再利用、思い出し補助。

| 仕様 | 内容 |
|---|---|
| 表示件数 | 直近 5〜8 件 |
| 各エントリ | 質問文（30字でtruncate）+ 相対時刻 |
| クリック動作 | 入力欄に質問文を流し込み、再質問可能 |
| 永続化 | localStorage（同一ブラウザ内で保持） |

### 2.4 📚 ナレッジ取り込み状況セクション
**目的**：「**何を学習済みか**」を可視化し、不足領域を発見可能にする。

| 項目 | 内容 |
|---|---|
| 取り込み済み文書数 | 数値表示（例: `6文書`） |
| 総チャンク数 | 数値表示（例: `22チャンク`） |
| カバー領域 | 文書タイトルから機械的に分類したカテゴリ列挙 |
| 最終取り込み | timestamp（例: `2026-04-27 14:23`） |
| **[+ ファイル追加] ボタン** | クリックでファイル選択ダイアログ／DnDも可。`.md` `.txt` 受付 |

**重要**：このセクションは**取り込み状態に応じて即時更新**する。文書追加→
- ナレッジセクション（文書数・チャンク数・カバー）の数字更新
- ウェルカム画面のサジェストチップを再生成
- 分析セクションのトップトピック候補追加

### 2.5 👍 フィードバックセクション
**目的**：回答品質の継続改善ループ。

| 項目 | 内容 |
|---|---|
| 累計 👍 / 👎 | 数値表示 |
| 改善要望リスト | 👎が付いた質問を最大3件、展開可能 |
| エクスポート | 管理者向けCSV出力（将来） |

## 3. メインエリア仕様

### 3.1 ヘッダー
| 要素 | 配置 | 内容 |
|---|---|---|
| 組織名 + アシスタント役割 | 左 | `[組織名]株式会社の社内ヘルプデスク` |
| ⚙ 開発者設定 | 右上 | クリックで開発者ツール（業界プリセット切替等）を展開 |
| ユーザー情報 | 右上 | ログインユーザーのメールアドレス、ログアウトリンク |

### 3.2 開発者ツール（⚙ クリック時に展開）
**配置**：ドロップダウンパネル（メインエリア右上）
**内容**：
- **業界プリセット切替**：`general / education / finance / healthcare`
  - 切り替えるとマスキングルールが変わる
  - **エンドユーザーには表示しない**（環境変数 `DEV_MODE=1` 時のみ歯車アイコンを出す想定）
- インデックス再構築ボタン
- 監査ログ閲覧リンク
- システム情報（バージョン、API状態）

### 3.3 ウェルカム画面（チャット未開始時）
| 要素 | 内容 |
|---|---|
| 見出し | `👋 どんなことでも聞いてください` |
| 説明 | `社内ドキュメントを参照して、出典付きで回答します` |
| **動的サジェストチップ** | **取り込み済み文書から自動生成**（以下参照） |

#### サジェスト生成ルール
1. 取り込み済み文書から各文書の代表質問を抽出
2. 文書内のチャンクを走査し、`### Q.` で始まる行を質問候補とする
3. 各文書から最大2件まで、合計6〜8件をランダム抽出して表示
4. 文書追加時は**自動で再生成**

### 3.4 チャットエリア
- 質問バブル：右寄せ青背景（`#1a73e8`）
- 回答バブル：左寄せ白背景＋出典カード
- マスキング適用時は、質問バブルの上に黄色バナーで「マスク後の文面」を表示
- 各回答に 👍／👎 フィードバックボタン

### 3.5 入力フォーム
- 下部固定、フルワイドのテキスト入力＋送信ボタン
- ローディング中は送信ボタン disabled、本文側にスピナー

## 4. 動的更新フロー（"取り込みデータが反映"の挙動）

```
[ファイル追加] (Sidebar > ナレッジ > [+ ファイル追加])
       │
       ▼
ファイル読み込み・チャンク化
       │
       ▼
DOCS state を更新
       │
       ├─→ Sidebar.ナレッジ → 文書数・チャンク数・最終取込時刻を更新
       ├─→ Sidebar.分析 → トップトピック候補を更新
       └─→ Main.ウェルカム → サジェストチップを再生成

[質問送信]
       │
       ▼
マスキング → 検索 → 回答生成
       │
       ├─→ Sidebar.分析 → 質問数+1、平均関連度を再計算
       ├─→ Sidebar.履歴 → 先頭に追加
       └─→ Main.チャット → メッセージ追加

[フィードバック (👍/👎)]
       │
       ▼
       ├─→ Sidebar.フィードバック → カウント更新
       └─→ 👎の場合 改善要望リストに質問追加
```

## 8. ナレッジ取り込み・クレンジング機能（v0.3）

サイドバーの **[+ ファイル追加]** ボタンクリックでモーダルを開き、3ステップで進める。

### 8.1 対応フォーマット

| 種別 | 拡張子 | パース方法 | 取り込み単位 |
|---|---|---|---|
| Markdown | `.md` | テキスト抽出 | 段落 |
| プレーンテキスト | `.txt` | テキスト抽出 | 段落 |
| PDF | `.pdf` | `pypdf` / `pdfplumber` | ページ |
| Excel | `.xlsx` `.xls` | `openpyxl` / `pandas` | シート×行範囲 |
| PowerPoint | `.pptx` `.ppt` | `python-pptx` | スライド |
| CSV | `.csv` | `pandas` | 行（ヘッダー自動検出） |
| 画像 | `.jpg` `.png` `.jpeg` | OCR（Tesseract or Claude vision） | 抽出テキスト全体 |
| **Google Drive** | フォルダ単位 | OAuth + Drive API | 上記各形式 |

> **外部データ連携（Slack / Confluence / Notion 等）は当面スコープ外**。

### 8.2 容量制限

| プラン | 1ファイル上限 | 総容量上限 | 備考 |
|---|---|---|---|
| Free Trial | 10MB | 100MB | 14日 |
| Standard | 50MB | 5GB | 1,000文書相当 |
| **Enterprise** | **200MB** | **50GB** | カスタム可 |
| On-Premise | 個別設定 | サーバ容量に依存 | 制限はホスト側 |

**UI挙動**：
- 容量プログレスバーをアップロード画面とサイドバーに常時表示
- 上限超過時は赤色アラート表示＋アップロード拒否
- プラン上限の80%到達でプランアップ案内バナー

### 8.3 クレンジング・パイプライン

```
[ファイル受信]
    │
    ▼
[1] フォーマット判定・パース ─→ 失敗ならエラー表示
    │
    ▼
[2] テキスト抽出 + チャンク化（段落 / 600字単位）
    │
    ▼
[3] セキュリティスキャン
    ├─ PII検出（メール・電話・マイナンバー・カード番号・IP・URL）
    ├─ 機密マーカー検出（"社外秘", "Confidential", "極秘", "[CONFIDENTIAL]"）
    ├─ 個人氏名候補（業界プリセット辞書 + NER）
    └─ 業界別ルール（教育=学校名・生徒名、金融=口座番号、医療=診療番号）
    │
    ▼
[4] 品質チェック
    ├─ 既存文書との重複度（コサイン類似度）
    ├─ 空ページ・低情報密度の検出
    ├─ OCR信頼度（画像の場合）
    └─ 文字化け検出
    │
    ▼
[5] 推奨アクション提示
    ├─ ✅ 取り込み可
    ├─ ⚠ 確認必要（マスキング推奨）
    └─ 🔴 取り込み非推奨（機密度高 or 品質低）
    │
    ▼
[6] ユーザー確認 → [取り込み実行] / [スキップ]
```

### 8.4 アップロード・モーダル仕様

#### Step 1: ファイル投入
- ドラッグ&ドロップ枠（中央に大きく）
- クリックでファイル選択ダイアログ
- 「Google Drive から取り込み」ボタン → OAuth → フォルダ選択UI
- 容量メーター（1.2GB / 5GB ▓▓░░ 24%）

#### Step 2: クレンジング結果表示（ファイルごとカード）
各カードに以下を表示：
| 項目 | 内容 |
|---|---|
| ファイル名・サイズ | アイコン付き |
| 判定バッジ | ✅取り込み可 / ⚠確認必要 / 🔴非推奨 |
| 抽出種類 | "テキスト + 表 5件 + 画像3件" 等 |
| チャンク数 | パース後のチャンク数 |
| 検出された懸念 | PII / 機密マーカー / 個人情報の件数 |
| 重複判定 | 類似%（既存文書名と並記） |
| アクション | [プレビュー] [編集] [取り込み] [スキップ] |

#### Step 3: 一括確定
画面下部に **[選択を確定して取り込む (N件)]** ボタン。クリックで：
1. マスキング適用後のテキストを RAG インデックスに追加
2. 監査ログに `event=ingest`, file, n_chunks 等を記録
3. サイドバーの「ナレッジ取り込み状況」を即時更新
4. ウェルカム画面のサジェストを再生成

### 8.5 セキュリティ判定の閾値

| 検出 | デフォルト判定 | 備考 |
|---|---|---|
| マイナンバー疑い | 🔴 非推奨 | 法的リスク高 |
| クレジットカード番号 | 🔴 非推奨 | PCI-DSS抵触可能性 |
| 個人氏名 5件以上 | ⚠ 確認必要 | マスキング推奨 |
| 「社外秘」「機密」マーカー | ⚠ 確認必要 | 管理者確認推奨 |
| メール・電話 | ⚠ 確認必要 | マスク後に取り込み可 |
| 既存文書と類似度 90% 以上 | ⚠ 重複の可能性 | 統合 or スキップ推奨 |
| OCR信頼度 50% 未満 | ⚠ 品質低 | 元画像の確認推奨 |

閾値は管理画面で組織ごとにカスタマイズ可能（v0.4以降）。

### 8.6 監査・トレーサビリティ

各取り込みアクションに対して以下を保存：
- 取り込みファイルハッシュ（SHA-256）
- 取り込み日時・ユーザー
- 検出された懸念とその対応（マスキング / 削除 / 無視）
- マスキング後の最終テキスト

→ 万一の事故時、「いつ・誰が・どんな懸念があった文書を取り込んだか」を完全追跡可能。
