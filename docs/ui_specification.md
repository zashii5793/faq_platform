## 0. 設計原則

1. **左サイドバーで利用状況・ナレッジ状態を常時可視化** — 「どの程度学習が進んでいるか」「過去にどんな質問が来たか」を一目で把握できる
2. **サジェスト・分析は取り込みデータ駆動** — 文書を追加すると自動でサジェストとカバレッジが更新される（ハードコード禁止）
3. **業界プリセットなどの開発者設定は隠す** — エンドユーザー画面には出さず、歯車アイコンの開発者ツールに格納
4. **回答には必ず出典を付ける** — ハルシネーション防止のための強い設計制約

## 2. サイドバー仕様（左 280px 固定）

### 2.1 ヘッダー部
| 要素 | 内容 |
|---|---|
| プロダクト名 | `Inquira`（青字、大） |
| 組織名 | `ZAXEL株式会社`（グレー、小） |

### 2.2 📊 分析セクション
**目的**：管理者・利用者が「ツールがどれだけ使われ／どれだけ役立っているか」を即座に把握。

| 項目 | データソース | 例 |
|---|---|---|
| 今日の質問数 | 監査ログから当日件数を集計 | `12件` |
| 平均関連度スコア | 各回答の上位ヒットスコアの平均 | `0.34` |
| トップトピック | top1ヒット文書の出現頻度 | `経費精算 (5)、VPN (3)` |

### 2.3 🕐 問い合わせ履歴セクション
**目的**：過去質問の即時再利用、思い出し補助。

| 仕様 | 内容 |
|---|---|
| 表示件数 | 直近 5〜8 件 |
| 各エントリ | 質問文（30字でtruncate）+ 相対時刻 |
| クリック動作 | 入力欄に質問文を流し込み、再質問可能 |
| 永続化 | localStorage（同一ブラウザ内で保持） |

### 2.4 📚 ナレッジ取り込み状況セクション
**目的**：「**何を学習済みか**」を可視化し、不足領域を発見可能にする。

| 項目 | 内容 |
|---|---|
| 取り込み済み文書数 | 数値表示（例: `6文書`） |
| 総チャンク数 | 数値表示（例: `22チャンク`） |
| カバー領域 | 文書タイトルから機械的に分類したカテゴリ列挙 |
| 最終取り込み | timestamp（例: `2026-04-27 14:23`） |
| **[+ ファイル追加] ボタン** | クリックでファイル選択ダイアログ／DnDも可。`.md` `.txt` 受付 |

**重要**：このセクションは**取り込み状態に応じて即時更新**する。文書追加→
- ナレッジセクション（文書数・チャンク数・カバー）の数字更新
- ウェルカム画面のサジェストチップを再生成
- 分析セクションのトップトピック候補追加

### 2.5 👍 フィードバックセクション
**目的**：回答品質の継続改善ループ。

| 項目 | 内容 |
|---|---|
| 累計 👍 / 👎 | 数値表示 |
| 改善要望リスト | 👎が付いた質問を最大3件、展開可能 |
| エクスポート | 管理者向けCSV出力（将来） |

## 3. メインエリア仕様

### 3.1 ヘッダー
| 要素 | 配置 | 内容 |
|---|---|---|
| 組織名 + アシスタント役割 | 左 | `ZAXEL株式会社の社内ヘルプデスク` |
| ⚙ 開発者設定 | 右上 | クリックで開発者ツール（業界プリセット切替等）を展開 |
| ユーザー情報 | 右上 | ログインユーザーのメールアドレス、ログアウトリンク |

### 3.2 開発者ツール（⚙ クリック時に展開）
**配置**：ドロップダウンパネル（メインエリア右上）
**内容**：
- **業界プリセット切替**：`general / education / finance / healthcare`
  - 切り替えるとマスキングルールが変わる
  - **エンドユーザーには表示しない**（環境変数 `DEV_MODE=1` 時のみ歯車アイコンを出す想定）
- インデックス再構築ボタン
- 監査ログ閲覧リンク
- システム情報（バージョン、API状態）

### 3.3 ウェルカム画面（チャット未開始時）
| 要素 | 内容 |
|---|---|
| 見出し | `👋 どんなことでも聞いてください` |
| 説明 | `社内ドキュメントを参照して、出典付きで回答します` |
| **動的サジェストチップ** | **取り込み済み文書から自動生成**（以下参照） |

#### サジェスト生成ルール
1. 取り込み済み文書から各文書の代表質問を抽出
2. 文書内のチャンクを走査し、`### Q.` で始まる行を質問候補とする
3. 各文書から最大2件まで、合計6〜8件をランダム抽出して表示
4. 文書追加時は**自動で再生成**

### 3.4 チャットエリア
- 質問バブル：右寄せ青背景（`#1a73e8`）
- 回答バブル：左寄せ白背景＋出典カード
- マスキング適用時は、質問バブルの上に黄色バナーで「マスク後の文面」を表示
- 各回答に 👍／👎 フィードバックボタン

### 3.5 入力フォーム
- 下部固定、フルワイドのテキスト入力＋送信ボタン
- ローディング中は送信ボタン disabled、本文側にスピナー

## 4. 動的更新フロー（"取り込みデータが反映"の挙動）

```
[ファイル追加] (Sidebar > ナレッジ > [+ ファイル追加])
       │
       ▼
ファイル読み込み・チャンク化
       │
       ▼
DOCS state を更新
       │
       ├─→ Sidebar.ナレッジ → 文書数・チャンク数・最終取込時刻を更新
       ├─→ Sidebar.分析 → トップトピック候補を更新
       └─→ Main.ウェルカム → サジェストチップを再生成

[質問送信]
       │
       ▼
マスキング → 検索 → 回答生成
       │
       ├─→ Sidebar.分析 → 質問数+1、平均関連度を再計算
       ├─→ Sidebar.履歴 → 先頭に追加
       └─→ Main.チャット → メッセージ追加

[フィードバック (👍/👎)]
       │
       ▼
       ├─→ Sidebar.フィードバック → カウント更新
       └─→ 👎の場合 改善要望リストに質問追加
```

## 7. 実装ロードマップ

| フェーズ | 内容 |
|---|---|
| **Phase A**（モックアップ） | 静的HTMLでUI完成形を作成 — 本仕様書 + `mockup_sidebar.png` |
| **Phase B**（クライアントサイド版） | `demo.html` を完全自己完結型に。File DnD で文書追加→即時反映 |
| **Phase C**（サーバ統合） | FastAPI 側に `/api/sidebar/state` エンドポイントを追加し、本物の集計結果を返す |
| **Phase D**（永続化） | 履歴・フィードバック・分析を社内DB（PostgreSQL）に保存 |
