📁 .env 設定ガイド（視覚版）

🎯 これだけ覚えればOK

.env = 本物の秘密鍵（パスワードのようなもの）→ 絶対にGitアップしない
.env.example = 空のテンプレート（書き方の見本）→ Gitアップして共有OK

Gitアップしようとしても .gitignore で自動的にブロックされる仕組みなので、誤操作で漏れる心配はありません。

🤔 そもそも .env って何？

アプリを動かすために必要な「設定値」をまとめたファイルです。例えば:

  • 🔑 Google OAuth の Client ID / Secret
  • 🤖 Anthropic の API キー（Claude AI を使うため）
  • 🌐 アクセスURL
  • 🔒 セッション暗号化のための秘密鍵

これらは パスワードと同じレベルの秘密情報 なので、ファイル1つにまとめて、コードとは分けて管理します。

🔒 Gitアップは安全？仕組みの解説

✅ 結論：仕組みで守られているので安全です。

仕組み①：.gitignore で自動除外

このプロジェクトの .gitignore ファイルには、すでに .env が登録されています。

__pycache__/
*.py[cod]
.venv/
.env       ← この行で除外されている
.env.local
*.log
...

これにより、git add . しても .env はステージに乗りません。間違えても安全です。

仕組み②：ファイル名で役割を分ける

ファイル名 中身 Git 用途
.env.example 空のプレースホルダー
GOOGLE_CLIENT_SECRET=xxxxx		 ✅ アップする 他の人が同じ設定を作る時の見本
.env 本物の値
GOOGLE_CLIENT_SECRET=GOCSPX-AbC...		 ❌ アップしない あなたのPCでアプリを動かすため

📝 作業手順

1 テンプレートから .env を作る

ターミナル（Mac は「ターミナル」アプリ、Windowsは「PowerShell」）を開いて以下を実行:

cd /home/user/faq_platform
cp .env.example .env
📌 これだけで、テンプレートの内容がコピーされた .env ファイルが作られます。
まだ中身はプレースホルダーのままなので、次のステップで書き換えます。
2 .env をエディタで開く

以下のどちらかで開けます:

  • VS Code を使っている場合: code /home/user/faq_platform/.env
  • テキストエディタ全般: /home/user/faq_platform/.env を「メモ帳」「TextEdit」等で開く
3 Google OAuth の3行を書き換える

編集前（テンプレートのまま）:

GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxxxx
GOOGLE_REDIRECT_URI=http://localhost:8000/auth/callback

編集後（あなたが入力する例）:

GOOGLE_CLIENT_ID=123456789-abcdefg.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-AbCdEfGhIjKlMnOp
GOOGLE_REDIRECT_URI=https://faq.inquira-ai.com/auth/callback

💡 値の取り方

GOOGLE_CLIENT_ID
Google Cloud Console → Clients → クライアント名クリック
画面右の「Client ID」の 📋 コピー アイコンをクリック
GOOGLE_CLIENT_SECRET
同じ画面の「Client secret」
•••••••• の右の 👁 表示 で見える化 → 📋 コピー
⚠️ チャットや画面共有で絶対に他人に見せない
GOOGLE_REDIRECT_URI
固定値: https://faq.inquira-ai.com/auth/callback
4 他の項目も埋める

同じファイル内の以下も編集します:

ORG_NAME
初期値: ○○株式会社
→ A社の正式名称に変更（例: 株式会社AAA）
ANTHROPIC_API_KEY
初期値: sk-ant-...
→ 本物のClaude APIキーに置き換え（sk-ant-api03-... という形式）
取得先: https://console.anthropic.com/
ALLOWED_EMAILS
アクセスを許可するメールアドレス（カンマ区切り）
例: hideki.ishizashi@gmail.com,担当者のメール@aaa-corp.co.jp
SESSION_SECRET
初期値: change-me-to-a-long-random-string
→ 次のコマンドで生成した長いランダム文字列に置き換え: 
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
DEMO_MODE
初期値: false のままでOK（本番モード）
5 保存して確認

エディタで保存（Cmd+S / Ctrl+S）したら、ターミナルで確認:

grep -E "^(GOOGLE_CLIENT_ID|GOOGLE_REDIRECT_URI|ORG_NAME)=" .env

期待される出力:

GOOGLE_CLIENT_ID=123456789-abc...apps.googleusercontent.com
GOOGLE_REDIRECT_URI=https://faq.inquira-ai.com/auth/callback
ORG_NAME=株式会社AAA
📌 Secret 系（CLIENT_SECRET, API_KEY等）はあえて表示していません。
画面共有時に漏れないようにする配慮です。

⛔ 絶対やってはいけないこと

🚨 これをやるとAPI料金請求や情報漏洩に直結します
  • ❌ .env ファイルをGitにコミット（→ GitHubに公開されると秘密鍵が世界中に漏れる）
  • ❌ Client Secret や API Key をチャット・メール・Slackに貼る
  • ❌ .env.example に本物の値を書く（テンプレートなのでGitアップされる）
  • ❌ スクリーンショットで .env の中身を撮影して送る

✅ やってOKなこと

  • ✅ .env をローカルPCに保存
  • ✅ .env を 1Password / Bitwarden 等のパスワード管理ツールにバックアップ
  • ✅ .env.example を Git にコミット（テンプレートとして共有）
  • ✅ Client ID（Secret ではない方）は公開しても基本OK（GoogleのOAuth仕様上、必ずブラウザに露出する）

🛡️ もし秘密鍵を漏らしてしまったら？

慌てず、以下を実行:

Google OAuth Secret を漏らした場合

  1. Google Cloud Console → Clients を開く
  2. 該当クライアントの「⋮」メニュー → Reset secret
  3. 新しい Secret が発行される（古いものは無効化）
  4. 新しい値を .env に書き直す

Anthropic API Key を漏らした場合

  1. Anthropic Console → API Keys を開く
  2. 該当のキーを Revoke（無効化）
  3. 新しいキーを Create → .env に書き直す
  4. 請求ダッシュボードで不正使用がないか確認

誤って .env を Git にコミットしてしまった場合

  1. すぐに上記の手順で Secret / API Key を Reset / Revoke
  2. Git履歴からの削除は git filter-repo 等が必要（私に依頼してください）
  3. GitHubにすでにpush済みの場合は、リポジトリを一旦Privateにしてサポートに連絡

📋 最終チェックリスト

  • cp .env.example .env を実行した
  • .env をエディタで開いた
  • Google Cloud Console から Client ID をコピーして貼り付けた
  • Google Cloud Console から Client Secret をコピーして貼り付けた
  • GOOGLE_REDIRECT_URI を https://faq.inquira-ai.com/auth/callback に変更した
  • ORG_NAME を A社の正式名称に変更した
  • ANTHROPIC_API_KEY を本物の値に置き換えた
  • ALLOWED_EMAILS に許可するメールを入れた
  • SESSION_SECRET を新しいランダム文字列に変更した
  • ファイルを保存した
  • grep コマンドで設定が反映されていることを確認した
  • 万が一に備えて、 .env の内容をパスワード管理ツールにバックアップした

❓ よくある質問

Q. .env をチームで共有したいときは？

A. 1Password / Bitwarden の「Secure Note」機能で共有するのがベストプラクティスです。Slack/メール添付は絶対NG。Gitに上げるのも論外。

Q. 開発用とは本番用で別の .env が必要？

A. はい。慣例として:

  • .env = 本番用
  • .env.local = 開発用（localhost向け）

どちらも .gitignore で除外済みなので安全です。

Q. Client ID は本当に公開してOK？

A. はい。Google OAuth の仕様上、Client ID はブラウザのHTMLに必ず露出します。秘密にする意味がないので、コードに直接書いてもセキュリティ上問題ありません。ただし慣習として .env に置きます。絶対に秘密にすべきなのは Client Secret の方です。

Q. うっかり .env を git add してしまった！

A. まだ git commit していなければ:

git reset HEAD .env

これで取り消せます。すでに commit してしまった場合は、すぐに Secret/API Key を Reset/Revoke してください。
