# A社 導入ガイド — 手順と料金の説明

> このドキュメントは **A社（クライアント）へ Inquira を導入する際の手順と、
> どこで・誰に・いくらお金が発生するか** を営業／導入担当が説明するための資料です。
>
> - `[組織名]` = 提供事業者（ZAXEL）を指します。公開リポジトリのため社名はプレースホルダにしています。
> - `__要記入__` = 金額は経営判断のため未確定。見積時に確定値を入れてください。
> - コストの細かい試算は [api_cost_analysis.md](./api_cost_analysis.md) を参照。

---

## 1. 全体像 — お金は「3つの宛先」に分かれて発生する

A社が支払う総額は、最終的に次の3者に分配されます。**これを混ぜて説明すると「高い／不透明」と思われる**ため、必ず分けて提示します。

```
A社が支払う総額
   │
   ├─ ① Claude API 利用料 ──→ Anthropic（実費・従量）
   │     質問1件ごとに課金。月額固定費なし。使わなければ0円。
   │     目安: 1質問あたり約2〜3円（Sonnet 4.6 / TF-IDF構成）
   │
   ├─ ② ホスティング費 ─────→ クラウド事業者（Render/AWS 等）
   │     サーバー・ドメイン・SSL。A社オンプレ設置なら此処はA社の既存設備。
   │
   └─ ③ [組織名] の取り分 ──→ ZAXEL の売上
         初期構築費 + 月額保守費 + サポート + 機能開発
```

| 宛先 | 性質 | 変動するか |
|---|---|---|
| ① Claude API | 実費・従量 | **質問数で毎月変動** |
| ② ホスティング | 実費・ほぼ固定 | プラン次第でほぼ一定 |
| ③ [組織名] | 役務の対価 | 契約で固定 |

> 💡 **説明のコツ**: 「①と②は実費でそのままお預かり、②③が当社の価値提供分」と切り分けると納得を得やすい。

## 2. 導入の流れ — 5フェーズと「お金が発生する瞬間」

| フェーズ | 主な作業 | 期間目安 | この時点で発生する費用 |
|---|---|---|---|
| **1. 契約・ヒアリング** | 業務範囲・対象文書・利用人数の確認、見積提示、契約 | 1〜2週 | （見積のみ・費用なし） |
| **2. 環境構築** | サーバー契約／ドメイン取得／SSL／Google OAuth 設定／`.env` 構成 | 3〜5日 | **初期構築費**（③）開始 ＋ **ホスティング**（②）開始 |
| **3. 初期データ投入** | A社の社内文書を `/admin` からアップロード → インデックス化 | 1〜3日 | 初期構築費（③）に含む |
| **4. テスト運用** | A社の数名で試用、回答精度の調整、しきい値チューニング | 1〜2週 | **Claude API 課金**（①）がここで初めて発生 |
| **5. 本番リリース** | 全社展開、運用開始 | — | **月額保守費**（③）＋ API実費（①）＋ ホスティング（②）が定常化 |

### 各フェーズの担当・必要なもの

- **フェーズ2** で A社に用意してもらうもの: Google Workspace 管理者権限（OAuth設定用）、利用するドメイン
- **フェーズ3** で A社に用意してもらうもの: FAQ化したい社内文書（マニュアル・規程・過去の問い合わせ等）
- 詳細手順は [setup_for_admin.md](./setup_for_admin.md) / [google_oauth_setup.md](./google_oauth_setup.md) / [https_deployment.md](./https_deployment.md) を参照。

## 3. 料金体系 — [組織名] が提示する3項目

A社への見積書はこの3行構成を推奨します。

| 項目 | 課金形態 | 金額（要確定） | 含まれるもの |
|---|---|---|---|
| **初期構築費** | 一括 | `__要記入__` 円 | 環境構築・OAuth設定・初期データ投入・操作レクチャー |
| **月額保守費** | 月額固定 | `__要記入__` 円/月 | 稼働監視・不具合対応・バージョンアップ・問い合わせサポート |
| **Claude API 実費** | 従量 | 実費（目安 後述） | Anthropic への支払い分（①） |

> ホスティング費（②）は「月額保守費に内包」「実費を別建て」のどちらか。
> [組織名] がまとめて契約・代行支払いするなら内包が説明しやすい。

### Claude API 実費の目安（A社規模で試算）

[api_cost_analysis.md](./api_cost_analysis.md) より、**35名規模の標準シナリオで月 15,000〜25,000円**。
利用人数・質問頻度で変わるため、見積では「想定レンジ」で提示します。

## 4. Claude API 課金の「2つの預かり方」 — ここを必ず合意する

①の Claude API は月ごとに変動します。**誰の Anthropic アカウントで契約し、誰が変動リスクを負うか** を契約時に決めます。

### 方式A: 実費パススルー（[組織名] が変動リスクを負わない）

```
A社の Anthropic アカウント or [組織名] が立替 → 翌月実費請求
```
- メリット: [組織名] のキャッシュアウトなし、透明
- デメリット: A社の月額が読みにくい（「先月いくら？」が毎月変わる）

### 方式B: [組織名] が定額で巻き取り（マークアップ込み）

```
[組織名] が API 実費を負担 → A社へは「月額◯円（API込み）」で固定請求
```
- メリット: A社は予算が立てやすい・請求書がシンプル
- デメリット: [組織名] が変動リスクを負う（質問激増月は持ち出しの可能性）
- 対策: 月間質問数の上限設定、プロンプトキャッシュ実装でコストを圧縮（[api_cost_analysis.md](./api_cost_analysis.md) §5）

> 💡 **推奨**: 初年度は方式Bで「月額◯円（API実費込み・想定◯問/月まで）」とし、
> 上限超過分のみ方式Aで精算するハイブリッドが、A社にとって分かりやすく [組織名] のリスクも限定的。

## 5. [組織名]（ZAXEL）の取り分はどう組み立てるか

A社が支払う総額のうち、**①②は実費で素通り、利益は③に乗せる**のが基本です。

```
[組織名] の粗利 = 初期構築費 + 月額保守費 −（実作業コスト）
                 (+ 方式Bを採る場合: 月額に乗せたAPIマージン − API実費)
```

取り分を決めるときの観点:

1. **初期構築費** — 構築の実工数（人日 × 単価）＋ ノウハウ対価。フェーズ2〜3の作業量が根拠。
2. **月額保守費** — 純粋な役務収益。ここが継続収益の柱。監視・更新・サポートの工数を時間換算 ＋ 利益。
3. **API マージン（方式B時）** — 変動リスクを引き受ける対価。実費に 10〜30% 程度上乗せが一般的。上乗せ無しなら方式Aと同じでリスクだけ負うことになるので注意。
4. **ホスティング** — 原則そのまま実費。代行契約の手間賃を少額乗せる程度。

> ⚠️ API実費（①）に大きく利益を乗せると「使うほど [組織名] が儲かる」構図になり、A社の不信を招きやすい。
> **利益は③（役務）に集約し、①は透明に**、が長期的な信頼につながります。

## 6. A社への説明トーク例

> 「料金は3つに分かれます。**1つ目は Claude の利用料**で、これは Anthropic 社への実費。
> 質問の数に応じた従量制で、御社35名規模だと月1.5〜2.5万円が目安です。
> **2つ目はサーバー費用**、**3つ目が当社の構築・保守費**です。
> 当社の利益は3つ目だけに乗せていて、1つ目・2つ目は実費でそのままお預かりします。
> ご予算を立てやすいよう、初年度は『月額◯円・API実費込み』の固定プランをご用意できます。」

ポイント:
- 「使わなければ Claude 利用料は0円」= 無駄が出ない設計だと伝える
- コスト抑制が実装済み（`min_score_threshold` で確信度の低い質問は API を呼ばない、TF-IDF検索で埋め込みAPI不要）であることを訴求 → [api_cost_analysis.md](./api_cost_analysis.md) §5
- Anthropic Console で月予算アラートを設定し**暴走課金を防止**できることを安心材料として添える

## 7. 契約前チェックリスト

- [ ] 初期構築費・月額保守費の金額を確定（§3 の `__要記入__`）
- [ ] API課金は方式A／B／ハイブリッドのどれか合意（§4）
- [ ] Anthropic アカウントの名義（A社／[組織名]）を決定
- [ ] ホスティング先を決定（Render / AWS / A社オンプレ）— [https_deployment.md](./https_deployment.md)
- [ ] Google Workspace 管理者の協力者を確保（OAuth設定）
- [ ] FAQ化する初期文書をA社から受領
- [ ] 月間想定質問数の上限を設定（方式B採用時）
- [ ] 契約書に無料／有料の区分・期間・上限を明記
