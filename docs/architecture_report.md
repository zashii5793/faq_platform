## 1. このツール (Inquira) は何ができるのか？

### ひとことで言うと

> **「会社の中にある資料を全部食べさせて、社員が質問したら出典付きで答える AI 受付係」**

### 具体的に言うと

社員が「経費精算の締め日いつでしたっけ？」とWebで質問すると…

1. 会社の文書（PDF / Excel / マニュアル等）を**自動で検索**
2. 関連する箇所を **Claude（AI）** に渡す
3. AI が文書の内容**だけを使って**回答を作成
4. 「経費規程.pdf p.3 を参照」のように **出典付き** で表示
5. 社員がボタンで👍/👎を押すと**精度改善のヒント**になる

### こういう人が使う

- ヘルプデスク部門：同じ質問に何度も答える時間を削減
- 新人：「あの人に聞かないと分からない」状態を解消
- 情シス：「マニュアルどこ？」を一掃
- 管理職：誰がどんな質問をしているか把握したい

## 3. 一番大事な話：「学習」ではなく「参照」している

これは技術選定の根幹なので、丁寧に説明します。

### よくある誤解

> 「AI に資料を**学習**させたら、機密情報が漏れない？」

これは半分正解、半分間違いです。

### 学習 vs 参照

このシステムは **学習ではなく参照** をしています。違いを図で：

#### ❌ 学習（Fine-tuning）— このシステムでは**やっていない**

```
[全文書 5GB] ───→ AIモデル本体に焼き込む ───→ 新しいAIモデル
                                                  │
                                                  └─► 質問に対して、
                                                      "覚えている知識"
                                                      から回答する
```

**問題点**：
- 焼き込み（学習）に時間とコストがかかる（数時間〜数日）
- 一度焼き込むと、文書を更新しても古い情報が残る
- AIモデルに情報が混ざるので、削除しづらい

#### ✅ 参照（RAG）— このシステムが採用している方式

```
[文書] ──保管──► 📚 自社の倉庫 (データベース)
                     ▲
                     │ 質問のたびに「関連する箇所だけ」取り出す
                     │
                  💬 AI（Claude）
                     │
                     │ 取り出した文書 + 質問 を見て回答
                     ▼
                  💡 出典付きの回答
```

**メリット**：
1. **文書の更新が即反映**（再学習不要）
2. **AIに情報を「覚えさせない」**ので、削除や差し替えが容易
3. **出典が明示できる**（どこから引っ張ってきたか分かる）
4. **学習されないので機密保護に強い**（Anthropicの商用APIは学習に使わない契約）

### 図書館の例えで言うと

| 学習方式 | 参照方式（このシステム） |
|---|---|
| 全本をAIに丸暗記させる | 司書がその場で本を探してきて、AIに読み聞かせる |
| 暗記後は本を捨てても答える | 本がないと答えられない（裏返すと、本を更新すれば即反映） |
| 何ページに書いてあるか言えない | 「○○.pdfのp.3 です」と言える |

> **だから「学習させる」と聞かれたら、正確には**
> **「参照できる場所に置く（取り込む）」と答えるのが正解** ✅

## 4. 一つの質問が処理されるまで（順を追って）

例：社員が「VPN繋がらない時どうしたら？」と質問した場合

```
社員        Web画面     サーバ     マスキング   検索    Claude   監査ログ
 │            │           │          │          │        │         │
 │── 質問 ──►│           │          │          │        │         │
 │           ├── POST ──►│          │          │        │         │
 │           │           ├─認証OK──►│          │        │         │
 │           │           │          │ メール等を│        │         │
 │           │           │ ◄─マスク─┤  伏せ字に│        │         │
 │           │           ├──── 検索 ────────►│        │         │
 │           │           │          │ ◄─関連3件─       │         │
 │           │           ├── 質問+関連文書 ────────►   │         │
 │           │           │                              │ AI が   │
 │           │           │                              │ 回答生成 │
 │           │           │ ◄─── 「FortiClient再起動を…」 ┤        │
 │           │           ├── 質問・出典・確信度 を ────────────►   │
 │           │ ◄─JSON─── │                                       │
 │           │ 表示      │                                       │
 │ ◄─画面表示┤           │                                       │
 │           │           │                                       │
```

### 確信度の判定（ハルシネーション抑制）

検索で関連性スコアが**0.08未満**なら、Claudeを呼ばず即「該当情報なし」を返します。

| 関連度 | 動作 | 表示 |
|---|---|---|
| 0.08未満 | **AIを呼ばない** | 🔴 該当情報なし |
| 0.08〜0.20 | AI呼ぶ | 🟠 確信度 30-60% |
| 0.20〜0.30 | AI呼ぶ | 🟡 確信度 70-85% |
| 0.30以上 | AI呼ぶ | 🟢 確信度 85-98% |

この仕組みにより **AIが「知ったかぶり」する前に止められる** のがポイントです。

## 5. ファイルが取り込まれるまで

例：「経費規程.pdf」をドラッグ＆ドロップした場合

```
①ファイル投入
   │
   ▼
②形式判定 ──► PDF と認識
   │
   ▼
③テキスト抽出 ──► ページごとに本文を取り出す
   │
   ▼
④チャンク化 ──► 600文字単位に区切る（細かく検索するため）
   │
   ▼
⑤PII検出 ──► メール・電話・マイナンバー等を探す
   │
   ▼
⑥推奨判定:
   ├ ✅ ok        : 懸念なし → 通常取り込み
   ├ ⚠ warn       : マスキング推奨 → マスクして取り込み
   └ 🔴 danger    : マイナンバー等あり → **取り込み拒否**
   │
   ▼
⑦マスキング適用 ──► [メール]・[電話番号] 等に置換
   │
   ▼
⑧FAQマスター保存 ──► 検索可能な形でDBに格納
   │
   ▼
⑨インデックス再構築 ──► 検索エンジンに反映
   │
   ▼
⑩監査ログ記録 ──► 「いつ・誰が・何を取り込んだか」+ SHA-256ハッシュ
```

### 重要：人間の最終判断を入れる設計

`/admin/upload` 画面で、解析結果を**カードで一覧表示**してから人間が「取り込む」or「スキップ」を選ぶ仕組み。

| カード色 | 判定 | UIの動き |
|---|---|---|
| 🟢 緑バー | ok | 自動で「取り込み対象」 |
| 🟡 黄バー | warn (PII等) | 自動で「取り込み対象」+ マスク予告 |
| 🔴 赤バー | danger (マイナンバー等) | **取り込み対象から除外**（スキップのみ可） |

→ 危険なファイルは UI レベル + サーバレベルで **二重に拒否** されます。

```
├─ data/
│   ├─ faq_master/           ← 取り込み済みFAQ（マスク済み）★1

│   │

│   │

│       ├─ audit-2026-04-26.jsonl
│       └─ audit-2026-04-27.jsonl
│
├─ tests/                    ← 自動テスト（39件）
└─ docs/                     ← 文書・スクショ
```

### ★1 FAQマスター（検索対象）

各文書は Markdown で保存されます：
```markdown
# 経費規程.pdf
_取り込み元: a3b89f4c..._
## 経費規程.pdf#p1
月次締めは毎月25日。
連絡先は [メール]、緊急時は [電話番号]。  ← マスク済み
```

### ★2 監査ログ（誰が何をしたか）

1行ごとにJSON形式：
```json
{"ts":"2026-04-27T22:34:23Z","event":"query","user":"taro@zaxel.co.jp","question":"VPN繋がらない","sources":["VPN接続.md#0"],"confidence":95,"answered":true}
{"ts":"2026-04-27T22:35:01Z","event":"ingest","user":"taro@zaxel.co.jp","filename":"経費規程.pdf","sha256":"a3b89f4c","n_chunks":47,"masked":true}
```

→ あとから「誰がいつ何を聞いたか」「どのファイルを取り込んだか」が **完全追跡可能**。

## 7. セキュリティの三重防御

このシステムは「機密情報が漏れる」リスクを**3層**で防いでいます。

### 第1層：誰が使うか（認証・認可）
- Google SSO（会社のGoogleアカウントでログイン）
- 許可されたドメイン（例：`@zaxel.co.jp`）のみアクセス可
- それ以外は **403 拒否**

### 第2層：何が外に出るか（マスキング）
質問にPIIが含まれていても、Claude API に送る前に伏せ字化：
| 元の表現 | マスク後 |
|---|---|
| `tanaka@zaxel.co.jp` | `[メール]` |
| `03-1234-5678` | `[電話番号]` |
| `1234 5678 9012`（マイナンバー） | `[マイナンバー]` |
| `××学園の山田先生` | `[学校名]の山田先生` (教育プリセット時) |

### 第3層：どこに保存されるか（データ主権）
- **Anthropic の商用 API は学習に使わない**（契約で保証）
- API ログは7日で自動削除（より厳しくする ZDR 契約も可）
- FAQ本文・監査ログは**自社サーバ**にしか保存されない
- 個人プラン（ChatGPT 等）の業務利用は禁止（学習に使われる）

## 8. 技術選定の理由（なぜこれを選んだか）

| 選んだもの | 候補 | 選んだ理由 |
|---|---|---|
| **FastAPI** (Pythonフレームワーク) | Flask, Django, Node.js | Python だと AI ライブラリが豊富 / FastAPI は型安全・速い |
| **Anthropic Claude** | OpenAI GPT, Google Gemini | **学習に使われない契約** / 日本語精度が高い / 長文に強い |
| **TF-IDF（簡易検索）** | Embedding (OpenAI text-embedding-3) | PoC段階。本番は Embedding に切替予定（ROADMAP Phase 1.1） |
| **Markdown（FAQ保存形式）** | DB, JSON | 人間が読み書きしやすい / Gitで差分追跡できる |
| **JSONL（監査ログ）** | DB, CSV | 1行追記で済む / 既存ツールで扱いやすい |
| **Google SSO** | 自前ID/パスワード | パスワード管理リスクをGoogleに任せられる |

## 10. 品質保証：どう「壊れていない」と確認しているか

開発の品質を以下で担保：

### A. 自動テスト（合計39件）
| 種類 | 件数 | 内容 |
|---|---|---|
| Unit（単体） | 27件 | 個々の関数（マスキング、検索、解析等）の正しさ |
| Integration（統合） | 12件 | API を跨ぐ実シナリオ（取り込み→質問→回答） |

### B. CI/CD（GitHub Actions）
- pushの度に Python 3.11 / 3.12 で全テスト実行
- ruff（Lint）でコード品質チェック
- 失敗したらマージできない

### C. 起動時テスト
- `./scripts/demo.sh` は**統合テストが通らないと起動しない**
- 「動いてるけど壊れてる」状態を防ぐ

## 11. まとめ：このシステムの価値

### 技術的な強み
1. **学習させない（参照のみ）** → 文書更新が即反映、機密保護に強い
2. **出典必須** → AIが嘘をつけない（ハルシネーション抑制）
3. **確信度可視化** → 「自信があるか」が見える
4. **三重防御** → 認証・マスキング・データ主権

### 事業的な強み
1. **既存資産活用** → 新規データ作成不要、既存PDFをそのまま使える
2. **段階導入** → 小さく始めて拡大可能（PoC → 部門 → 全社）
3. **業界横展開** → 業界プリセット化で営業効率化
4. **コスト構造** → 月¥10万 × 10社 で月100万 ARR が見える

### 利用者にとっての価値
1. **欲しい情報が10秒で出る**（人間に聞くと10分待つ）
2. **24時間365日対応**
3. **質問を恥ずかしがらなくていい**（AI相手だから何度でも聞ける）
4. **新人オンボーディング期間が半減**（先輩の時間を奪わない）

## 用語集（あいうえお順）

| 用語 | 意味 |
|---|---|
| API | プログラム同士が情報をやりとりする仕組み |
| Claude | Anthropic 社が作った AI（このシステムが使う回答エンジン） |
| Embedding | 文章を数値ベクトルに変換する技術。意味の近さを計算できる |

| ハルシネーション | AI が事実でないことを自信ありげに答える現象 |
| JSONL | 1行ずつ JSON が書かれたファイル形式（追記しやすい） |
| Markdown | 文書フォーマットの一種（軽量、人間が読みやすい） |
| OCR | 画像から文字を読み取る技術 |
| OAuth | 安全に他サービスのアカウントでログインする仕組み |
| PII | Personally Identifiable Information（個人を特定できる情報） |
| RAG | Retrieval-Augmented Generation（参照を強化した生成 = このシステムの方式） |
| SHA-256 | ファイルの「指紋」を計算する仕組み（改ざん検知に使う） |
